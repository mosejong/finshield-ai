아래는 전부 구현·배포되어 공개 URL 에서 동작하는 기능이다. 미구현 기능은 이
칸에 넣지 않았다.

[ 포함 — 구현 완료 ]

- 사기 위험 분석 : 문자·메시지 원문 입력 → 위험 등급 3단계 / 위험 점수 /
  위험 신호 15종 / 사기 유형 10종 판정. LLM 미호출.
- 사용자 상태 반영 : 7종(받기만 함 / 링크를 눌렀음 / 개인정보를 알려줬음 /
  계좌·인증 접근권을 넘겼음 / 앱을 설치했음 / 모르는 돈이 입금됐음 / 송금했음).
  상태에 따라 최소 위험 등급과 대응 행동, 화면 톤이 바뀐다.
- 대응 행동 제시 : 12종 중 상황에 맞는 것을 우선순위대로. 각 행동에 공식 연락처.
- 공식 근거 제시 : 사기 분석 카탈로그 8건(금융보안원 2 · 경찰청 2 ·
  한국인터넷진흥원 2 · 법령 2)과 전세보증금 카탈로그 9건. 출처·수집시각 표시.
- AI 설명 생성 : 결정론 결과를 사회초년생이 읽을 문장으로. 출력 검증 4종을
  통과했을 때만 표시.
- 공식 금융상품 : 금융위원회 공공데이터 기반 조회 / 상세 / 2개 비교.
- 금융 프로필 : 생성·조회·수정·삭제와 파생지표 3종(백엔드 결정론 계산).
- 대출 조건 시뮬레이션 : 현재 조건과 대안 조건 비교. 계산은 전부 백엔드.
- 목표 기반 상품 후보 : potential_match / mismatch / needs_review 3분류.
- 전세보증금 위험 점검 : 만원 단위 입력. 세션 불필요 · 저장 안 함 ·
  외부 호출 없음 · LLM 없음.
- 재테크 기초 가이드 : 공식 금융교육 근거 기반. 입력·종목·매매 추천 없음.
- PWA : 설치, 문자 앱 공유 시트 진입(원문을 주소에 싣지 않도록 POST),
  오프라인 셸.
- 운영 : /health, /health/live, /health/ready, /internal/metrics.
- 보안·프라이버시 : 익명 세션 / HttpOnly·SameSite=Strict 쿠키 / DB 에는
  SHA-256 해시만 / 미소유 자원 404 / 필드 단위 암호화 / IP 기준 요청 한도.

- 금융기관 실시간 연동
- 계정 기반 로그인
- 공식 근거 자동 갱신

[3칸] 사용자 이용 흐름
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[ 흐름 A — 의심 문자를 방금 받음 (최우선 경로 · 로그인 불필요) ]

 1. 문자 앱에서 [공유] → FinShield 선택.
    (또는 공개 URL 접속 → "위험한 금융 연락 확인")
 2. 문자 원문이 입력창에 붙는다.
    PWA 공유 타깃을 POST 로 전달하므로 URL 에 원문이 남지 않는다.
 3. "이미 무엇을 하셨나요?" 상태를 고른다. 7종이며 기본값은 "받기만 했다".
 4. [확인하기] 를 누른다.
 5. 결과 화면이 나온다. 순서가 고정돼 있다.
      ① 위험 수준        문장이 먼저, 숫자 점수는 접혀 있다
      ② 감지된 위험 신호  무엇이 켜졌는지
      ③ 왜 위험한지      AI 설명 (검증을 통과했을 때만)
      ④ 이미 한 것       선택한 상태의 요약
      ⑤ 지금 할 행동     우선순위대로, 공식 연락처는 tel: 링크
      ⑥ 공식 근거        기관 · 문서명 · 수집시각
 6. 상태를 잘못 골랐으면 결과 화면에서 바로 바꾼다. 행동 목록이 다시 계산된다.

 3번이 이 서비스의 축이다. 같은 문자라도 "받기만 함" 이면 예방 행동 5개가,
 "송금함" 이면 수습 행동 9개와 특별법 근거가 나온다.

[ 흐름 B — 이미 넘어감 (수습) ]

 - 흐름 A 의 3번에서 "송금했다" / "계좌 접근을 허용했다" / "개인정보를 줬다"
   중 하나를 고른다.
 - 화면 문구가 예방에서 수습으로 전환된다.
 - ⑤ 지금 할 행동 최상단에 즉시 조치가 고정된다.
   112 신고 → 1394 상담 → 거래 금융기관 즉시 연락 → 기록 보존 …
 - ⑥ 공식 근거에 「전기통신금융사기 피해 방지 및 피해금 환급에 관한 특별법」이
   추가된다.

[ 흐름 C — 평상시 (금융 판단) ]

 - 공개 URL → 홈. 블록은 정확히 넷이다.
   ① 현재 금융상태  ② 지금 확인할 금융정보  ③ 위험한 금융 연락 확인  ④ 다음 행동
 - [선택] 온보딩 → 금액·구간·목표만 입력한다. 건너뛸 수 있다.
 - 내 금융상태 → 파생지표 3종. 계산은 백엔드가 한다.
 - 금융상품 → 조회 → 상세 → 2개 비교 → 대출 조건 시뮬레이션.
 - 전세보증금 위험 점검 → 만원 단위 입력. 저장하지 않는다.
 - 재테크 기초 가이드 → 공식 근거 기반.

 흐름 A 는 흐름 C 를 요구하지 않는다. 프로필은 개인화 품질만 올리는 선택
 요소이고, 의심 문자를 받은 사람에게 가입을 요구하면 이탈하기 때문이다.

[4칸] AI 및 데이터 처리 방식
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[ 4-1. 처리 순서 ]

사용자 입력
 ① 입력 검증 · 개인정보 최소화
    주민등록번호·비밀번호·OTP·카드 전체정보를 받지 않는다.
    사용자가 넣은 URL 을 서버가 조회하지 않는다.
 ② 결정론 판정 엔진   ← LLM 없음. 같은 입력이면 같은 결과.
    위험 등급 / 점수 / 위험 신호 15종 / 사기 유형 10종
 ③ 사용자 상태 반영 (7종)   ← LLM 없음
    대응 행동 12종 중 선택하고 우선순위를 정한다.
 ④ 공식 근거 결합 (8건)   ← LLM 없음
 ⑤ 생성형 AI 설명   ← 여기 한 곳에서만 모델을 부른다.
    주 모델   : Gemini 3.6 Flash
    대체 모델 : Gemini 3.1 Flash-Lite (주 모델 실패·거부 시 1회)
    프롬프트 입력 = ②③④의 결과와 공식 근거 블록. 모델이 판단할 여지가 없다.
    ★ 근거 블록이 전부 비어 있으면 호출하지 않는다 → status: not_asked
 ⑥ 출력 검증
    기관 / 법령 / 수치 / 약속. 근거 밖이면 문장을 폐기하고 대체 모델을 부른다.
    그래도 실패하면 문장 없이 표시한다.
 → 화면 (고정 6단)

⑤ 이외의 모든 단계에 LLM 이 없다. 위험 판정·점수·사기 유형·대응 행동·공식 근거
선택·금융 계산은 전부 결정론 코드다. 금융 계산은 프론트엔드에도 없다. 전부
백엔드에서 계산된 값이 내려온다.

[ 4-2. 설명 계층의 네 가지 상태 ]

- ready      : 문장이 검증을 통과함 → ③ 왜 위험한지 에 문장을 표시한다.
- not_asked  : 근거가 없어 모델을 부르지 않음 → ③ 을 그리지 않는다 (정상 동작).
- off        : 설명 계층 비활성 → ③ 을 그리지 않는다.
- failed     : 문장이 검증에 걸려 폐기됨 → ③ 을 그리지 않는다.

이 넷을 하나로 뭉치지 않는다. 뭉치면 정상 동작(not_asked)이 화면에서 고장으로
보고된다. 평가셋에서 이 상태가 나오는 비율이 37% 였다.

[ 4-3. 개인정보 처리 여부 ]

수집하지 않는 항목 (명시적 금지) :
주민등록번호 · 은행 비밀번호 · OTP · 카드 전체 정보 · 불필요한 계좌번호.

- 인증 방식 : 익명 세션. 아이디·비밀번호·이메일·전화번호를 받지 않는다.
- 세션 발급 : POST /api/v1/auth/session
- 세션 저장 : 원문은 HttpOnly · SameSite=Strict 쿠키에만 둔다.
  DB 에는 SHA-256 해시만 저장한다.
- 소유권 검증 : 모든 프로필 접근에서 세션 사용자와 owner 일치를 검증한다.
- 미소유 자원 : 404 를 반환한다. 403 이 아니다. 자원의 존재 여부를 노출하지
  않기 위해서다.
- 금융 프로필 : 금액·구간·목표만 받고 DB 에 필드 단위로 인증 암호화한다.
- 문자 원문 : 판정에 사용한다. 공유 진입이 POST 라 URL·브라우저 기록에 원문이
  남지 않는다.
- 전세보증금 점검 : 세션 불필요, 저장하지 않음, 외부 호출 없음, LLM 없음.
- 운영 로그 : 카운트와 성공/실패만 기록한다. 사용자·세션·프로필 식별자와 금융
  원문을 기록하지 않는다(허용목록 방식).
- 사용자 URL : 서버가 조회하지 않는다. 사용자가 넣은 URL 은 적대적 입력으로
  취급한다.
- 삭제 : DELETE /api/v1/auth/session (세션만),
  DELETE /api/v1/auth/account (계정과 전체 금융정보).
- 외부 전송 : 설명 생성 시 결정론 판정 결과와 공식 근거가 Google AI Studio 로
  전송된다. 프로필 원문은 전송하지 않는다.
- 고지 : 모든 분석·시뮬레이션·가이드 응답에 확정 판단이 아님을 알리는
  disclaimer 가 포함되며 화면에서 생략할 수 없다.

  동결됩니다. 수사기밀이므로 가족을 포함해 누구에게도 알리지 마시고, 원격 확인

[ 5-3. 시나리오 2 — 같은 문자, 이미 송금한 경우 (상태 축 검증) ]

[ 5-5. 시나리오 4 — 전세보증금 위험 점검 (저장 없는 계산) ]

경로 : 「안전 확인」 → 「전세보증금 위험 점검」 (/check/deposit)

샘플 입력값 (금액은 만원 단위)
- 계약 단계 : 잔금·입주 (6종 중 선택)
- 보증금 : 20000  (2억 원)
- 매매 시세 : 25000  (2억 5천만 원)
- 선순위 채권최고액 : 10000  (1억 원)

예상 결과
- 위험 수준 : low / medium / high 중 하나. 점수는 만들지 않는다. 가중치를
  조정할 실측 데이터가 아직 없기 때문이다.
- 부채비율 : (선순위 채권최고액 + 보증금) ÷ 주택가격 × 100 = 120.0%
- 보호 상태 : 대항력 발생일, 대항요건·우선변제권 요건 충족 여부
- 위험 신호 : 11종 중 해당하는 것
- 할 일 : 9종 중 해당하는 것. 전부 공식 근거 id 를 가진다.
- 공식 근거 : 국가법령정보센터 · 법제처 · 주택도시보증공사 9건 중 해당분

확인 포인트
- 로그인이 필요 없고, 입력값을 저장하지 않으며, 외부 API 도 LLM 도 호출하지
  않는다.
- 빈 칸은 0 이 아니라 모름(null)으로 처리된다. 선순위 채권을 0 으로 채우면
  등기부를 안 본 사람에게 가장 안전해 보이는 숫자를 주게 된다.
- 구간 이름(60% / 80%)은 이 서비스의 보수적 기준이며 공식 고시가 아니다.
  응답의 band_is_service_rule, 신호 문장, disclaimer 세 곳에 같은 사실이 적혀 있다.
- 만원 단위 입력은 사회초년생이 0 을 아홉 개 세지 않게 하려는 것이고,
  ×10,000 은 단위 환산이지 금융 계산이 아니다.

[ 5-7. 검증된 품질 지표 ]

- 정밀도 0.9872 : 독립 held-out 평가셋 12개 누적 865건
- 재현율 0.9789 : 같은 대상
- F1 0.9830 : 같은 대상
- 오탐률(FPR) 0.0153 : 같은 대상
- 공식 근거 coverage 1.000 : held-out 평가셋 12개 전부
- 판정 API 지연 p50 2.807ms / p95 3.979ms : 개발셋 1,220 샘플
- 판정 API 지연 p50 2.925ms / p95 3.866ms : held-out v1.3, 252 샘플

held-out 평가셋은 매 회차 수정 코드보다 먼저 동결해 커밋했다. 커밋 순서는

처음 보는 평가셋에서의 F1 은 0.44 ~ 0.98 이었고, 위 값은 평가셋 12개를 지금
엔진 하나로 다시 잰 값이다. 이 둘을 구분해서 적는 것이 이 프로젝트의 규칙이다.

[ 5-8. MVP 제한 사항 ]

○ 기능 범위
- 텍스트 입력만 지원한다. 음성(STT)·화면 캡처·이미지 분석은 이번 범위 밖이다.
- 사용자가 넣은 URL 을 서버가 조회하지 않는다. URL 은 문자열로만 분석한다.
  적대적 입력을 서버가 따라가는 것 자체가 취약점이기 때문이다.
- 금융기관 실시간 연동이 없다. 지급정지는 공식 창구 안내까지이고 실제 정지
  요청은 사용자가 직접 한다.
- 로그인·계정 기능이 없다. 익명 세션만 지원하므로 기기를 바꾸면 프로필이
  이어지지 않는다.

○ 데이터
- 공식 근거(사기 분석 8건, 전세보증금 9건)는 정적 fixture 다. 출처·수집시각
  스키마는 보존하고 있으나 자동 갱신은 아직 아니다.
- 금융상품은 금융위원회 공공데이터의 최신월 snapshot 이며 실시간 금리가 아니다.

○ 정확도
- 이진 판정은 F1 0.9830 이지만 유형 이름 붙이기는 아직 만점이 아니다. 가장
  약한 유형은 isolation_coercion(F1 0.898, 정밀도 0.855 / 재현율 0.946)이며,
  놓치는 쪽(미탐)이 아니라 아닌 것을 그 유형으로 부르는 쪽(오탐)으로 틀린다.
- 누적 865건 기준 오탐 6건과 미탐 10건이 남아 있고, 어느 건인지 문서에 적혀 있다.
- 의료·법률적 확정 판단이 아니다. 모든 응답에 그 고지가 포함된다.

○ AI 설명
- 검증을 통과하지 못하면 문장 없이 판정 결과만 표시된다. 이때도 위험 등급·
  대응 행동·공식 근거는 정상 표시된다.
- 설명 문장의 사실 검증기는 아니다. 근거 밖의 것을 말하면 거른다는 뜻이지,
  통과한 문장이 근거에 정확히 붙어 있음을 판정하는 것은 아니다.
