# ADR 0004: 익명 데이터 삭제와 만료 정리 정책

- 상태: Accepted
- 결정일: 2026-08-13
- 범위: 익명 사용자, 인증 세션, FinancialProfile 생명주기

## 배경

익명 세션과 profile 소유권은 사용자 간 격리를 제공하지만, 세션 쿠키가 만료·삭제되면 profile은 복구할
수 없는 상태로 남는다. 세션 폐기와 개인정보 삭제도 같은 동작으로 보이면 사용자가 실제 삭제 범위를
오인할 수 있다.

## 결정

1. 세션 폐기와 익명 계정·개인정보 삭제를 별도 API와 UI로 분리한다.
2. 사용자가 계정 삭제를 확인하면 소유 FinancialProfile 전체, 익명 사용자, 관련 세션 전체를 삭제한다.
3. 금융정보를 먼저 삭제하는 privacy-first 순서를 사용한다.
4. 활성 세션이 하나도 없는 익명 사용자를 만료 정리 대상으로 삼는다.
5. 정리 도구는 기본 dry-run이며 `--execute`가 있어야 변경한다.
6. 운영 로그에는 건수와 성공 여부만 기록하고 사용자·세션·프로필 식별자 및 금융 원문은 남기지 않는다.
7. 복구 수단이 없는 현재 익명 MVP에서는 세션 만료 뒤 별도 장기 보존 유예를 두지 않는다.
8. 백업의 물리적 파기는 온라인 삭제와 별도 운영 정책으로 관리한다.

## 대안

- 세션 삭제 시 profile도 자동 삭제: 사용자가 단순 로그아웃을 개인정보 삭제로 오인할 수 있고 다중 세션
  확장을 막아 기각했다.
- 만료 profile을 무기한 보존: 복구 경로 없이 민감 데이터만 남기므로 기각했다.
- 모든 만료 session row만 삭제하고 user/profile 유지: 접근 불가능한 금융정보가 고아 상태로 남아
  기각했다.
- 정리 명령을 기본 실행 모드로 제공: 운영 실수의 영향이 커서 dry-run 기본값을 선택했다.

## 결과

- 장점: 사용자에게 삭제 범위를 명확히 알리고, 접근 불가능한 금융정보가 장기 잔존하는 것을 방지한다.
- 비용: 정기 스케줄러와 백업 보존·파기 운영 절차가 필요하다.
- 한계: 온라인 삭제 직후 기존 백업·WAL의 선택적 레코드 파기까지 보장하지 않는다. 정식 계정 전환과
  데이터 복구는 별도 설계가 필요하다.
