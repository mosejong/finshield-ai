- `explanation-prompt-v2.md` — **규칙은 자기가 겨냥하지 않은 다섯 곳을 고쳤고, 겨냥한 한 곳은 못 고쳤다.** 앞 회차가 남긴 숫자(164건 중 6건에서 없는 연락처, 그중 다섯이 이미 돈이 움직인 뒤)를 보고 지시문을 `fraud_explanation_v1` → `v2` 로 올렸다. 더한 세 줄: **받은 문자는 근거가 아니다**(거기 적힌 번호는 보낸 쪽이 고른 값이다), 근거에 번호가 없으면 어디로 연락하라는 대신 무엇이 정상 절차와 다른지만 말한다, medium/high 에서 안전하다고 말하지 않는다. **한 회차에 한 변경** — 엔진·셋·모델 그대로. 결과: **지어낸 연락처 7시도/6사례 → 2시도/1사례**, 같은 조건 반복 실행에서 같은 값. 사라진 다섯(`fh-1038`·`fh-1040`·`fh-1065`·`fh-1147`·`fh-1170`)은 전부 `high` 이고, 전부 v1 에서 **주 모델이 거부당하고 대체 모델이 받아 준** 자리였다 — 그 안전을 검증기와 재시도로 사고 있었다(대체 모델 사용 4→1, 3→0). 그런데 **두 번째 규칙을 쓰게 만든 `fh-1007` 은 그대로다**: 다시 불러 보니 모델은 연락처를 제안하는 게 아니라 "해당 문자는 112 신고 접수 결과에 대한 안내로 확인됩니다" 라고 **문자가 무엇인지 설명**하는 중이고, 검증기의 번호 패턴은 **"112 로 전화하세요" 와 "이것은 112 안내입니다" 를 구분하지 못한다.** 검증기를 열지 않는다 — **오거부는 문장 하나를 잃고, 오통과는 사기범이 고른 번호를 공식 안내의 얼굴로 내보낸다.** 한쪽이 압도적으로 비싸면 모호한 자리는 비싼 쪽을 피해 닫는다. 고칠 자리는 프롬프트도 검증기도 아니고 **근거가 비면 아예 부르지 않는 것**이며, 두 변경을 한 번에 넣으면 줄어든 숫자가 어느 쪽 덕인지 말할 수 없으므로 다음 회차로 미뤘다. 그리고 v1.3 에서 판정 뒤집기가 1→3 으로 **늘었는데**, 세 사례를 15회 재호출해 0건 재현·같은 셋 반복 실행에서 0/49 — **`temperature=0.0` 은 결정론이 아니고 이 표의 값은 한 자릿수라, 같은 조건이 저절로 얼마나 움직이는지 모르면 개선과 잡음을 가를 수 없다.** 그래서 반복 실행 파일도 커밋한다. 부수: `_explanation_layer` 가 **지시문 sha256** 도 봐서 다른 프롬프트에서 잰 값은 `stale`(없었다면 보고서가 v1 의 숫자를 계속 `measured` 로 내놓았을 것이다), 결과 파일 이름에 지시문 판을 넣고(덮어썼다면 `docs/34` 13절이 인용하는 값이 조용히 사라진다) v1 프롬프트는 sha256 검사와 함께 저장소에 남겼다 — **나아졌다는 말은 무엇과 비교했는지가 남아 있을 때만 확인 가능한 주장이다.** 덤: 문장이 짧아졌고(p50 233→217, 220→201), 안전 필터 차단은 328시도째 0.

- `explanation-skip-empty-evidence.md` — **두 회차가 답을 고치려 했는데 문제는 질문 쪽이었다.** 13절이 "엔진이 할 말이 없을 때 모델은 말을 만든다" 고 적고 14절이 그 자리를 지시문으로 막으려다 겨냥한 한 건(`fh-1007`)을 못 고친 뒤, 이번엔 **근거 블록 셋이 전부 `- 없음` 이면 모델을 부르지 않게** 했다 — 프롬프트도 검증기도 엔진도 셋도 모델도 그대로고 바뀐 것은 **언제 부르는가** 하나다. 분기는 `risk_level == "low"` 이 아니라 **프롬프트에 실제로 들어가는 블록**을 본다(두 셋에서 정확히 같은 집합을 가리키지만 — `low`+근거 있음 **0건** — 같은 값인 것과 같은 뜻인 것은 다르고, 등급으로 분기하면 `low` 에 신호가 하나 붙는 날 조용히 설명을 잃는다). 결과: **164건 중 61건이 호출 없이 끝났고**(유료 시도 168 → 105, 37.5% 감소) 설명이 못 나간 사례 **0**, 지어낸 연락처 **0** — **검증기는 한 글자도 안 바뀌었는데 `fh-1007` 이 사라졌다.** 그리고 **분모를 안 바꿨다면 아무것도 실패하지 않은 회차에서 v1.3 이 0.5833 으로 찍힌다** — 비율이 재는 것은 물어본 것 중 몇이 답을 받았는가이지 세상의 몇 퍼센트가 설명을 받았는가가 아니다(`not_asked_rate` 를 따로 낸 이유). 화면에는 **상태가 세 개** 필요했다 — `explanation === null` 하나로 뭉치면 그 61건에서 제품이 스스로 고장 났다고 보고한다(37%의 사용자에게). `off` 와 `not_asked` 는 똑같이 아무것도 안 그리지만 합치지 않았다 — **같은 모양인 것과 같은 일인 것은 다르다.** 부수: `_EMPTY_BLOCK` 리터럴이 블록 생성 쪽에 세 번 흩어져 있어 **새 규칙을 지키는 코드가 새 규칙을 어기고 있었고**, `call_policy` 를 실행 파일에 넣어 벤치마크의 낡음 판별 축을 셋 sha·지시문 sha 에 이어 셋으로 늘렸으며(없으면 옛 표가 `measured` 로 나간다), 새 필드로 깨진 개인정보 가드는 **`==` 를 `<=` 로 푸는 대신** 옛 파일 여섯 개에 참인 값 `"call_policy": "ask_always"` 를 채워 고쳤다. 테스트 하나가 **통과할 뻔했다** — 판정 검사 분모 테스트가 새 규칙에서 시도 0 이 되어 재려던 것이 아니라 다른 것을 재게 되므로, `low` 인데 신호가 붙은 합성 판정을 넣어 되살렸다. 안 잰 것: 문장이 길어진 것(p50 217→242)은 **모집단이 바뀐 결과**이지 품질이 아니고, 지연은 두 셋에서 반대로 움직였으며, 그 61건에서 결정론 요약만으로 충분한가는 여전히 숫자가 없다
