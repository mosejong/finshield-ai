# 2026-09-04 — 근거가 준 법령을 되읽었다고 거부하고 있었다

## 어떻게 찾았나

앞 회차가 백로그에 두 줄을 열어 두고 끝났다.

- `evaluation/results/` 의 프로브 결과 여덟 개가 **전부 2026-08-25** 다. 근거
  이탈 검사는 08-27 에 들어갔다. **지금 코드로는 아무도 재 본 적이 없다.**
- 고친 기관 규칙 **자체의** 오거부율은 안 쟀다. 26.9% 는 **옛** 규칙이 죽인
  건수이고, 새 규칙이 0 이라고 주장한 적은 없다.

두 줄은 같은 실행 하나로 닫힌다. 홀드아웃 v1.2·v1.3 을 지금 코드로 다시 태웠다.

```
v1.2  물어본 55/80   설명 55/55   대체 모델 1건   근거 이탈 1
v1.3  물어본 49/84   설명 48/49   대체 모델 4건   근거 이탈 5
```

**v1.3 에 설명이 아예 없는 사례가 하나 있다.** `fh-1135` 다.

```
fh-1135  gemini-3.6-flash       rejected_law_citation
         gemini-3.1-flash-lite  rejected_law_citation
```

주 모델과 대체 모델이 **같은 사유로** 걸렸다. 모델 둘을 세워 둔 이유가
"같은 이유로 함께 죽지 않게" 인데(`runtime.py`), **규칙이 틀리면 둘은 다른
모델일 뿐 다른 규칙이 아니다.**

## 사유

`fh-1135` 에 엔진이 붙인 근거를 찍어 봤다.

```
- 인증정보 요구
- (1순위) 인증정보와 금융 접근수단을 공유하지 마세요 — …
- 경찰청: 보이스피싱 통합신고대응센터 1394 안내
- 국가법령정보센터: 전자금융거래법 제6조 접근매체의 선정과 사용 및 관리
```

마지막 줄이 전부다. **엔진이 공식 근거로 법령을 붙였고, 그 줄이 그대로
프롬프트에 들어간다.** 모델에게 법령을 읽히고, 모델이 그 법령을 되읽자
검증기가 죽였다.

법령 검사만 허용 목록이 없었다.

```python
if _LAW_PATTERN.search(explanation):        # 무조건 거부
    raise LlmOutputRejected(...)
```

연락처는 근거에 대조하고, 기관도 근거에 대조하고, 숫자는 근거와 문자에
대조한다. 법령 하나만 대조 없이 거부했다. 코드에 적힌 근거는 이랬다 —
"설명에 조문 번호가 필요한 경우가 없으므로". **틀린 전제였다.** 계좌·인증
접근권을 넘긴 사건, 즉 이 서비스에서 가장 위중한 상태에 엔진 자신이 법령을
붙인다.

**앞 회차의 기관 규칙과 같은 자리에서 같은 모양으로 틀렸다.** 근거에 있는
것을 없다고 센 것이고, 이번에는 대조를 잘못한 것이 아니라 대조를 아예 하지
않았다.

## 남은 거부 넷은 무엇이었나 — 다시 불러 봤다

같은 실행에서 기관 거부가 넷 있었다(`fh-1044`, `fh-1116`, `fh-1121`,
`fh-1162`). 넷 다 대체 모델이 받아 냈으므로 사용자는 설명을 봤지만, 새 규칙의
오거부인지 아닌지는 그것과 별개다. 다섯 사례를 주 모델로 다시 태웠다.

**다섯 다 통과했다.** 같은 입력, 같은 프롬프트, `temperature=0.0`.

그래서 다섯 건을 각각 5회씩 더 돌렸다(주 모델 25회).

| 사례 | ok | 거부 |
|---|---:|---|
| `fh-1044` | 4 | `rejected_ungrounded_org` 1 |
| `fh-1116` | 5 | — |
| `fh-1121` | 4 | `rejected_ungrounded_org` 1 |
| `fh-1135` | 4 | `rejected_law_citation` 1 |
| `fh-1162` | 5 | — |
| **합계** | **22** | **3** |

**남은 거부는 사례의 성질이 아니라 출력의 흔들림이다.** `temperature=0.0` 은
결정론을 보장하지 않는다 — 계약 주석이 이미 그렇게 적고 있었고(`"0.0 이
결정론을 보장하지는 않지만"`), 이 표가 그 문장의 실측값이다.

이 사실은 한 줄을 더 말한다. **한 회차의 프로브 숫자 하나를 지표로 읽으면 안
된다.** 아래 "잰 숫자" 에 같은 코드의 실행 둘을 나란히 둔 이유다.

## 기관 쪽은 고치지 않았다 — 왜인지 적어 둔다

걸린 토큰 둘은 이랬다.

```
'경우경찰청통합신고대응센터'
'신고는경찰청통합신고대응센터'
```

모델이 "…한 경우 **경찰청 통합신고대응센터**에…" 라고 썼다. 근거에는
`경찰청` 도 있고 `보이스피싱 통합신고대응센터` 도 있다. **낱말은 둘 다 근거에
있고, 붙여 놓은 이름이 근거에 없다.**

고치려면 어절 경계 뒷조각을 **일치**가 아니라 **부분 문자열**로 열거나, 앞에
붙은 어절이 근거의 기관이면 떼어 내는 규칙을 넣어야 한다. 둘 다 앞 회차가
일부러 닫아 둔 문이다 — 부분 문자열로 열면 `국세청 신고시스템` 이 근거의
`사이버범죄 신고시스템` 을 빌려 통과하고, 그 문장을 읽은 사람은 국세청이
운영하는 창구가 있다고 읽는다. 그 두 줄은 테스트에 얼려 놓여 있다.

**값이 다르다.** 법령 쪽은 사례 하나의 설명을 통째로 없앴고, 기관 쪽은 호출
하나를 더 쓰고 대체 모델이 받아 냈다. 제출 직전에 안전 검사를 느슨하게 여는
쪽은, 잃은 것이 호출 하나일 때 할 일이 아니다.

## 고친 것

법령 검사를 연락처·기관과 **같은 방식**으로 바꿨다.

```python
statutes = _ungrounded_laws(explanation, grounded_text)
if statutes:
    raise LlmOutputRejected(...)
```

`_ungrounded_laws` 는 법률 이름과 조문 번호를 **따로** 본다. 근거가
`전자금융거래법 제6조` 를 달고 왔을 때 `예금자보호법 제6조` 는 조문 번호만
빌린 문장이고 `전자금융거래법 제9조` 는 이름만 빌린 문장이다. 하나만 보면
둘 중 하나가 통과한다.

**이 변경으로 거부가 늘어나는 입력은 없다.** 통과하던 문장은 전부 그대로
통과하고, 죽던 문장 중 근거가 준 법령을 되읽은 것만 살아난다. 그 방향을
테스트 하나가 지킨다(`test_the_law_check_widened_and_never_narrowed`).

대조는 부분 문자열이라 이름을 줄여 쓴 것은 붙지 않는다 —
`전기통신금융사기 피해 방지 및 피해금 환급에 관한 특별법` 을
`전기통신금융사기특별법` 으로 줄이면 거부된다. 정규화가 지우는 것은 공백과
구두점뿐이고 글자 순서는 남기 때문이다.

## 테스트가 왜 이것을 못 잡았나

`tests/test_llm_ungrounded_claims.py` 의 근거 fixture(`GROUNDED`)에 **법령이
한 줄도 없었다.** 정상 문장 41개도, 지어낸 문장 18개도 전부 그 fixture 위에서
돈다. 근거가 법령을 달고 오는 상태가 테스트에 존재하지 않았으므로, 그 상태에서
무엇이 죽는지 물어본 적이 없다.

**셋이 조용한 것은 안전하다는 뜻이 아니라 셋이 안 물어봤다는 뜻이다.** 이번이
네 번째다(`납부` 어휘, `_ORG_PATTERN`, 낡은 프로브 결과, 그리고 이번).

`GROUNDED_WITH_LAW` 를 넣고 9개를 더했다.

- 근거가 준 법령을 되읽는 정상 문장 3개 → 통과해야 한다
- 이름만·번호만·줄여 쓴 것·무관한 법령 4개 → 여전히 거부돼야 한다
- 넓히기만 했다는 것 1개
- `_LAW_PATTERN` 이 못 잡는 것 1개 — **띄어 쓴 법률 이름**(`정보통신망 이용법`)
  은 `[가-힣]{2,}` 가 공백을 못 넘어 아예 안 걸린다. 꼬리만으로 잡으러 가면
  방법·수법·불법이 함께 죽으므로 지금은 열어 두고 `STILL_PASSING` 에 적었다.
  통과를 요구하는 테스트이고, 나중에 잡히면 실패로 알려 준다.

## 잰 숫자

같은 코드의 실행 둘을 나란히 둔다. **둘의 차이는 대부분 출력의 흔들림이지 이
수정의 효과가 아니다.** 이 수정이 증명한 것은 프로브의 차이가 아니라 위
단위 테스트다.

| | v1.2 고치기 전 | v1.2 고친 뒤 | v1.3 고치기 전 | v1.3 고친 뒤 |
|---|---:|---:|---:|---:|
| 사례 | 80 | 80 | 84 | 84 |
| 물어본 건수 | 55 | 55 | 49 | 49 |
| 안 물어봄 (근거 없음) | 25 | 25 | 35 | 35 |
| **설명이 나간 건수** | 55/55 | 54/55 | **48/49** | **49/49** |
| 대체 모델까지 간 사례 | 1 | 3 | 4 | 1 |
| 유료 호출 | 56 | 58 | 53 | 50 |
| `rejected_law_citation` | 0 | 0 | **2 (시도)** | **0** |
| `rejected_ungrounded_org` | 1 | 2 | 3 | 0 |
| 지어낸 연락처 | 0 | 1 | 0 | 0 |
| 안전 필터 차단 | 0 | 0 | 0 | 0 |
| 글자 수 min / p50 / max | 179/239/304 | 170/238/327 | 151/222/294 | 138/224/286 |

고친 뒤 v1.2 의 실패 하나는 `fh-1013` 이고 사유는
`rejected_contradicts_verdict` — 대체 모델이 `medium` 사건에 안심시키는 문장을
냈다. **이것은 맞는 거부다.** 고친 뒤 v1.2 의 `지어낸 연락처 1건`(`fh-1030`,
주 모델)도 맞는 거부이고, 대체 모델이 받아 냈다.

합계로 물어본 104건 중 **설명이 나간 것은 103건(0.99)**, 유료 호출은 108회로
사례당 **1.038회**다.

기록은 `evaluation/results/explanation-probe-fraud-holdout-v1.{2,3}-grounding-checks.json`
두 개이고, **고친 뒤 실행**이다. 원문도 모델 문장도 들어 있지 않다 —
건수·사유·소요시간·글자 수뿐이다(`adr/0006`).

기존 여덟 개(`-prompt-v1`, `-prompt-v2*`)는 지우지 않았다. 그것들은 **지시문과
호출 정책을 비교한 회차의 기록**이고, 지금 코드의 숫자가 아니라는 사실이
파일 이름과 `probed_at` 에 남아 있다.

## 덤으로 — 제출 원고가 다른 계층의 지연을 인용하고 있었다

새 프로브가 준 주 모델 지연이 p50 7.5초라, 문서에 적힌 값과 맞는지 훑었다.
다섯 자리에 이 줄이 있었다.

```
| 설명 LLM 호출 (61건 실측) | p50 2.21초 / p95 5.41초 |
```

숫자의 출처를 찾아 봤다.

```
llm-judge-fraud-v0.1.json  latency_ms  n=61  p50 2210.26ms  p95 5410.16ms
```

**설명 계층의 값이 아니다.** `docs/32` 3절의 **LLM-only 판정 비교** 61건,
즉 모델이 우리 엔진 대신 판정을 내리게 해 본 회차의 지연이다. `docs/28`
504줄과 `docs/32` 108줄은 이것을 "판정 지연" 이라고 정확히 적고 있는데,
`docs/35`·`docs/36`·`docs/38` 로 옮겨 적히면서 **"설명 LLM 호출" 이 됐다.**

낡은 값이 아니라 **계층이 바뀐 값**이라 더 나쁘다. 낡은 값은 다시 재면 되지만
이것은 다시 재도 영영 안 맞는다. 그리고 방향이 하필 유리한 쪽이었다 — 실제
설명 호출은 그 세 배 넘게 걸린다.

`docs/38` 은 제출 원고다. 271줄과 698줄, 두 번 들어가 있었다.

지금 코드로 잰 값으로 바꿨다(`-grounding-checks` 두 파일, 유료 호출 108회 중
주 모델 104회).

| | 주 모델 | 대체 모델 |
|---|---:|---:|
| 표본 | 104 | 4 |
| p50 | 7.52초 | 약 2.1초 |
| p95 | 9.23초 | — |
| 최대 | 10.27초 | — |

대체 모델 쪽은 **표본이 4건이라 p95 를 쓰지 않았다.** 표에 "표본이 적다" 를
같이 적었다.

**회차 간 비교로 쓸 수 없다는 것도 같이 적었다.** 같은 셋 v1.2 가 08-25 에
p50 2.82초, 09-04 에 7.40초다. 코드가 아니라 그날의 응답이 흔들린 것이고,
위 25회 반복이 말한 것과 같은 이야기다.

`docs/38` 의 `자동화 테스트 1,238건` 도 두 자리에서 1,247 로 고쳤다.

## 안 한 것

- **기관 조합 이름**(`경찰청 통합신고대응센터`)은 그대로 거부된다. 위에 값을
  적어 두었다.
- **띄어 쓴 법률 이름**은 여전히 안 잡힌다. `STILL_PASSING` 에 있다.
- 나머지 열 개 홀드아웃 셋과 개발셋은 안 쟀다. 이번에 잰 것은 v1.2·v1.3 둘이다.
- 흔들림의 폭을 제대로 재려면 같은 셋을 여러 번 돌려야 한다. 다섯 사례 25회가
  전부이고, 셋 전체 반복은 유료라 안 했다.
- 배포 환경 지연은 여전히 안 쟀다. 위 숫자는 전부 개발기에서 프로바이더로
  직접 부른 값이다.
