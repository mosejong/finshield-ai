# 제출 원고 외부 검수 — 맞은 것, 틀린 것, 내가 낸 흠

**2026-09-05 · `docs/38-submission-forms.md`, `docs/submission/*.txt`**

제출 이틀 전, 사용자가 다른 모델에게 원고 두 벌을 통째로 읽히고 그 검수 결과를
들고 왔다. 여덟 항목이었다. 전부 저장소와 대조했다. 여섯이 맞았고, 하나는
숫자가 맞았지만 내 손이 닿지 않는 일이었고, 하나는 사용자만 답할 수 있는
질문이었다. 그중 제일 뼈아픈 것은 **어제 내가 쓴 규칙을 어제 내가 어긴 것**이다.

## 1. 팀명이 두 원고에서 갈라져 있었다

`form1-plan-paste.txt` 머리말:

> 팀명 : 개인 참가는 팀을 만들지 않아 대조할 등록 팀명이 없다. 양식에 칸이
> 있으면 비워 두지 말고 본인 이름을 적는다.

`form2-spec-paste.txt` 머리말:

> 팀명 : daker.ai 에 등록한 팀 이름을 글자 하나 다르지 않게 옮긴다.

같은 제출물 두 장이 사람에게 **서로 다른 값을 적으라고 지시**하고 있었다.
한쪽은 `모세종`, 한쪽은 등록 팀명이다. 이대로 채웠으면 심사자는 팀명 칸이
다른 두 개의 PDF 를 받는다.

어제 참가 형태를 **1인 팀 `FinShield AI`** 로 뒤집으면서 `docs/38` 0절과
`docs/submission/README.md` 는 고쳤고, form1 머리말은 그대로 두고 나왔다.
그런데 어제 못 박은 규칙이 정확히 이것이었다 —

> **`docs/38` 을 먼저 고치고 그다음 이 두 `.txt` 를 맞춘다.** 반대로 하면 원고가
> 두 벌로 갈라지고, 어느 쪽이 제출본인지 알 수 없게 된다.

규칙을 쓴 그 커밋에서 규칙을 어겼다. **규칙을 문서에 적는 것과 지키는 것은
다른 일이고, 어긴 것을 잡아 준 것은 내 검증 스윕이 아니라 외부 독자였다.**
내 스윕은 마크다운 잔재·칸 수·줄 폭·은어만 본다. **두 파일이 같은 것을
말하는지는 아무도 안 보고 있었다.**

처음 고칠 때는 양쪽 머리말에 이름 `FinShield AI` 를 **값으로 박았다.**
"등록한 팀 이름을 옮긴다" 는 지시문은 등록이 안 됐을 때 빈칸으로 끝나기
때문이다. 그런데 그 값 자체가 곧 뒤집혔다.

## 1-2. 그런데 팀 등록 자체를 보류했다

머리말을 맞추고 나서 검수가 한 번 더 왔고, 이번 것이 더 중요했다.

> 요강은 개인 참가자가 **팀 신청 없이 참가 가능**하다고 명시하고 있고, 팀을
> 만들면 제출 전에 **팀으로 전환**까지 해야 한다. 이미 개인으로 신청했다면
> **제출 직전에 참가 형태를 바꾸는 셈**이다.

0절은 "양식에 팀명 칸이 있다" 는 이유 하나로 팀 등록을 **할 일**로 적어 두고
있었다. 그 칸은 서류 한 줄이고, 참가 형태는 **자격**이다. 서류 한 줄을 채우려고
자격이 걸린 상태를 제출 이틀 전에 건드리는 것은 교환비가 맞지 않는다.

0절 제목을 「참가 형태 — **1인 팀**」에서 「**확인하고 정한다** (2026-09-05
보류)」로 바꾸고, 3-1 표의 3번을 「팀 등록 후 기입」에서 「**현재 참가 상태를
먼저 확인**하고 그 상태에 맞춰 기입」으로 바꿨다. 팀 이름·설명·공개 설정 표는
지우지 않고 **"팀을 등록하기로 정했을 때 넣을 값"** 으로 내려 뒀다 — 판단이
바뀐 것이지 그때의 계산이 틀린 것은 아니고, 등록하기로 하면 그 표가 그대로
쓰인다.

그래서 원고 머리말도 **값을 박는 대신 두 갈래를 다 적었다.**

```
- 팀명 : daker.ai 의 현재 참가 상태를 먼저 확인하고 그 값을 옮긴다.
    · 팀 등록을 마쳤으면 등록한 이름 FinShield AI 를 글자 하나 다르지 않게.
    · 아직 개인 참가면 본인 이름 모세종 을 적는다. 비워 두지 않는다.
    두 장에 같은 값을 적는다. 한 장만 다르면 다른 참가자로 보인다.
```

**두 파일에 같은 다섯 줄이 들어갔다.** 1번의 결함은 값이 틀린 것이 아니라 두
파일이 서로 다른 말을 한 것이었으므로, 값이 아직 안 정해졌더라도 **같은 말을
하게 만드는 것**이 고침이다.

## 2. API 경로 다섯 줄에 `/api/v1` 이 없었다

`app/main.py` 는 기능 라우터를 전부 그 접두어 아래 붙인다.

```python
app.include_router(products_router, prefix="/api/v1")
```

그런데 기능명세서 2칸의 F-03 ~ F-07 은 `GET /products`, `POST /loans/simulate`
처럼 적혀 있었다. F-01·F-02·F-09·F-10 은 접두어가 붙어 있었다. **같은 표
안에서 절반만 맞았다** — 원본 표에서 한 줄씩 옮겨 적을 때 어떤 줄은
`docs/36` 에서, 어떤 줄은 기억에서 왔기 때문이다.

기능명세서는 심사자가 그대로 호출해 볼 수 있는 문서다. 적힌 대로 치면 404 다.
세 파일 전부 고치고, 검사기에 **"`GET|POST|PUT|DELETE` 뒤의 경로가
`/api/v1`·`/health`·`/internal` 로 시작하지 않으면 실패"** 를 넣었다.

## 3. 전세 샘플의 예상 결과가 「셋 중 하나」였다

검증 방법 5-5 는 샘플 입력값을 주고 예상 결과를 이렇게 적고 있었다.

> 위험 수준 : low / medium / high 중 하나

**검증 방법 칸에서 예상 결과가 선택지면 검증이 아니다.** 무엇이 나와도 맞는
말이 된다. 엔진을 실제로 돌렸다.

```
stage=balance_paid, 보증금 2억, 시세 2억 5천, 선순위 1억
→ risk_level = high, ratio 120.0% (band high)
→ 신호 5건 / 할 일 5건 / 근거 5건
```

`high` 로 확정하고 **건수까지 적었다.** "11종 중 해당하는 것" 은 대조할 수
없고 "11종 중 5건" 은 대조할 수 있다. `점수는 만들지 않는다` 는 설계 문장은
그대로 뒀다 — 그건 등급이 무엇이냐와 다른 얘기다.

## 4. 테스트 수가 1,256 이 아니라 1,258 이었다

원고 세 곳이 `1,256건`, 확인 방법은 `CI (GitHub Actions)` 라고 적고 있었다.
로컬 `pytest -q` 는 **1,256 passed, 2 skipped** 이고, CI 로그는

```
1258 passed, 1 warning in 16.54s
```

이다. 건너뛰던 두 건이 CI 에서는 DB 가 있어 돈다. **숫자 옆에 적어 둔 확인
방법과 숫자의 출처가 서로 달랐다.** 세 곳을 `1,258` 로 고치되 숫자만 바꾸지
않고 **`GitHub Actions CI 기준. 로컬은 DB 연동 2건이 건너뛰어져 1,256건`**
이라고 기준을 같이 적었다 — 심사자가 저장소를 받아 로컬에서 돌리면 1,256 이
나오고, 기준이 없으면 그게 불일치로 보인다. `docs/32`·`35`·`36` 의
`1,256 passed, 2 skipped` 는 로컬 실행 결과를 그대로 적은 것이라 사실이므로
두었다.

## 5. 세션 문구 — 무엇의 원문인지 안 적혀 있었다

> 세션 저장 : 원문은 HttpOnly · SameSite=Strict 쿠키에만 둔다.

개인정보 항목 표 안에서 "원문" 은 **문자 원문**으로 읽힌다. 바로 아래 줄에
`문자 원문 : 판정에 사용한다` 가 있다. 실제로 쿠키에 들어가는 것은
`app/services/auth_sessions.py` 의 세션 토큰이다. **`세션 토큰 원문`** 으로
이름을 붙였다.

같은 칸에서 `로그인·계정 기능이 없다` 와 `DELETE /api/v1/auth/account (계정과
전체 금융정보)` 가 나란히 있었다. 계정이 없다면서 계정 삭제 API 가 있다.
라우트 함수 이름은 `delete_anonymous_account` 이고, 실제로 지우는 것은 익명
세션과 그 소유자의 금융 프로필 전부다. **`회원가입·로그인 기반 계정이 없다`**
와 **`익명 사용자 데이터와 전체 금융 프로필`** 로 갈랐다.

## 6. 과단정 — 넷은 고치고 하나는 안 고쳤다

| 문장 | 처리 |
|---|---|
| 기존 대응 수단은 이 순간에 **닿지 않는다** | → `잘 닿지 않는다` |
| 검색하면 **또 다른 사기 페이지가 나온다** | → `검색어가 곧 사기 문구라 무엇이 공식 안내인지 가려내기 어렵다` |
| 넘어간 사람을 위한 자리가 **어디에도 없다** | → `설 자리는 드물다` |
| 사기의 첫 접점이 **거의 항상** 텍스트다 | → `문자·메신저인 경우가 많다` |
| 피해자는 판단력이 없는 사람이 아니라, 확인할 곳을 차단당한 사람이다 | **그대로 둔다** |

검색 문장은 완화가 아니라 **교체**다. "또 다른 사기 페이지가 나온다" 는 근거를
못 대지만, "검색어가 곧 사기 문구라 공식 안내를 가려내기 어렵다" 는 앞 문단이
이미 세워 둔 논지이고 더 정확하다. **약하게 만든 게 아니라 맞는 말로 바꾼 것에
가깝다.**

마지막 것은 안 고쳤다. 그 문장은 3칸의 논지 전체이고, 바로 앞 세 절(권위 사칭 ·
확인 경로 차단 · 시간 압박)이 그 결론을 향해 쌓여 있다. **완화하면 자기 논지를
자기가 안 믿는 문서가 된다.** 검증할 수 있는 주장에는 숫자를 붙이고, 논지에는
꼬리표를 안 다는 것이 이 원고의 규칙이다.

## 7. 내가 할 수 없는 두 가지

- **공개 URL 외부망 재검증.** 요강은 `2026-09-07 11:00 ~ 09-11 23:59` 접근
  가능을 요구하고 불가하면 결격이다. 이 PC 에 gcloud 도 SSH 도 없어 배포 상태를
  직접 못 본다. 5G·시크릿 모드로 사용자가 직접 확인해야 한다.
- **daker.ai 의 현재 참가 상태.** 개인 참가인지 팀 등록을 마쳤는지는 그 계정
  화면에만 있고, 나는 그 계정에 접근할 수 없다. 원고는 **어느 쪽이어도 붙도록**
  두 갈래를 같은 문장으로 적어 뒀다. 애매하면 운영사에 묻는 것이 제일 싸다 —
  틀리면 서류가 아니라 참가 자격이 흔들린다.

## 8. 문서가 권하던 두 가지 안전장치가 안전하지 않았다

3-1 표의 남은 항목 둘도 같이 걸렸다. 둘 다 **적어 둔 대로 하면 제출 기간에
서비스가 죽는** 종류다.

**예산 알림은 지출을 멈추지 않는다.** 표는 「**Google Cloud 예산 알림 + 일
상한** 설정」이라고 적어 알림이 상한인 것처럼 읽히게 두고 있었다. 예산 알림은
경고 메일이고 자동 차단이 아니다. 실제 상한은 API 별 할당량 쪽에 건다 —
**Generative Language API 의 일일 할당량**. 이쪽에 걸면 한도를 넘겼을 때 죽는
것은 AI 설명 한 층이고, **웹서비스와 결정론 판정은 살아 있다.** 결제를
끊는 방식으로 상한을 걸면 VM 이 같이 내려가고, 심사 기간에 URL 이 죽으면
결격이다. **알림은 낮게, 할당량은 넉넉히.**

**Gemini 키 IP 제한은 거는 순서가 있다.** 표는 IP `104.198.12.219` 에 걸라고만
적고 있었다. 그 주소는 `docs/devlog/2026-08-25` 가 확인한 `finshield-ai.duckdns.org`
의 A 레코드이고 VM 의 외부 주소다. 문제는 **그것이 예약된 고정 주소인지 임시
주소인지 이 문서 어디에도 안 적혀 있다**는 것이다. 임시(ephemeral) 주소면 VM 이
한 번 재시작되는 순간 주소가 바뀌고, 키 제한은 남아 있으므로 **AI 설명이 전부
조용히 죽는다.** 표에 **고정 IP 확인 → 제한 → 공개 URL 에서 설명 생성 1회
확인** 순서를 적었다. 제한을 걸고 확인을 안 하는 것이 8월 25일에 `chmod 600`
으로 서비스를 내렸을 때와 같은 모양이다.

## 남는 것

검증 스윕이 **한 파일 안**만 본다는 것이 이번의 진짜 결함이다. 마크다운 잔재도
줄 폭도 은어도 파일 하나를 열고 세면 나온다. 팀명은 두 파일을 나란히 놓아야
보인다. 이번 스윕에 경로 검사는 넣었지만 **두 원고의 머리말이 같은 말을
하는지 보는 검사는 아직 없다.** 제출이 끝나면 만든다 — 지금 새 검사를 짜다가
원고를 건드리는 것이 더 위험하다.
