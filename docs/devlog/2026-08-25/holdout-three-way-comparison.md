# 2026-08-25 — held-out 에서 다시 잰 3자 비교, 그리고 모델이 이겼다

## 왜 지금

2026-08-19 의 3자 비교는 이 문장으로 끝나 있었다.

> 두 숫자는 이제 같은 조건의 비교가 아니며, 다시 비교하려면 held-out 셋에서
> 둘 다 다시 재야 한다.

엿새 동안 못 갚은 이유는 하나다 — **유료 호출이 안 나갔다.** 공개 URL 의
Gemini 경로를 살린 날(`public-redeploy-v0.3.0.md`) 그 이유가 없어졌다.

## 재는 자에서 먼저 막혔다

돈을 쓰기 전에 stub 으로 배관을 통과시켰고, 거기서 걸렸다.

```
ValidationError: case_id
  String should match pattern '^fg-[0-9]{3}$'  input_value='fh-1101'
```

`LlmJudgement.case_id` 가 **개발셋 번호만** 받고 있었다. 홀드아웃이 생기기 전에
쓰인 필드이고, 열두 회차 동안 아무도 이 경로로 홀드아웃을 판정시킨 적이 없어서
남아 있었다.

값이 비싼 자리다. 이 검증은 **모델 응답을 받아 온 뒤에** 돈다. 실제로 태웠다면
84건의 응답을 받아 놓고 파일 쓰기 직전에 죽었을 것이다.

같은 규칙이 두 곳에 적혀 있던 것이 원인이다 — `FraudGoldenCase` 는
`^(?:fg|fh)-[0-9]{3,4}$` 로 이미 넓혀져 있었다. **같은 규칙을 두 곳에 적으면
한 곳만 넓어진다.** 상수 하나(`CASE_ID_PATTERN`)로 합치고, 공유가 풀리는 것을
잡는 테스트를 붙였다.

두 번째로 걸린 것은 러너가 `dataset_id="fraud_golden_v0.1"` 을 **박아 두고**
있던 것이다. `--dataset` 을 받으면서 이름은 개발셋으로 쓰니, 홀드아웃을 판정한
파일이 자기를 개발셋이라고 말한다. sha256 이 어긋나 집계는 `stale` 로 막히지만,
그때 사람이 읽는 것은 이름이다. **파일 하나로 출처가 확인된다는 전제가 이름에서
먼저 깨진다.**

## 잰 것

| | |
|---|---|
| 셋 | held-out v1.2 (80건), v1.3 (84건) |
| 모델 | `gemini-3.6-flash`, temperature 0.0 |
| 프롬프트 | `fraud_judge_v1` (2026-08-19 과 동일, sha 고정) |
| 결과 | 164건 전부 응답, 실패 0건, 어휘 밖 코드 0건 |
| 지연 | v1.2 p50 2.05s / p95 6.26s, v1.3 p50 2.11s / p95 5.66s |

## 엔진 숫자를 두 개 적어야 했다

held-out 회차는 **얼리고 → 재고 → 고친다.** 그래서 같은 셋에 엔진 숫자가 두
개 있다. 모델에게는 그 두 번째 열이 없다 — 이 셋을 한 번 보고 한 번 답했고,
그 답으로 모델을 고칠 방법이 우리에게 없다.

그러므로 모델 옆에 놓아야 하는 것은 **동결 시점** 열이다. 수정 후 열을 놓으면
2026-08-19 에 개발셋으로 했던 편향을 방향만 바꿔 반복하는 것이 된다.

| | v1.2 | v1.3 |
|---|---:|---:|
| 엔진 F1 (동결 시점) | 0.4384 | 0.6032 |
| **모델 F1** | **0.9677** | **0.9882** |
| 엔진 F1 (그 셋으로 고친 뒤) | 0.9783 | 1.0000 |

**두 배 가까이 진다.** 그리고 탐지만 지는 것이 아니다.

| | v1.2 엔진(동결) → 모델 | v1.3 엔진(동결) → 모델 |
|---|---|---|
| 상태 정책 정확도 | 0.650 → **0.775** | 0.690 → **0.881** |
| 필수 행동 coverage | 0.505 → **0.782** | 0.453 → **0.919** |

2026-08-19 에 "그다음 세 줄이 규칙에 판정 권한을 남겨 둔 이유" 라고 적었던
바로 그 항목들이다. **개발셋에서는 그 세 줄이 우리 편이었고, 처음 보는
문장에서는 아니다.**

## 이 표를 홍보물로 만드는 방법이 하나 있다

수정 후 열만 보여 주는 것이다. 그러면 "엔진 1.0000, 모델 0.9882" 가 되고,
아무도 거짓이라고 말할 수 없다. 그렇게 적지 않았다. 이 저장소가 열세 회차
동안 지켜 온 규칙 하나가 **정직하게 진다/이긴다** 이고, 오늘이 그 규칙이
실제로 값을 요구한 날이다.

동시에 한쪽으로 기울여 읽지 않기 위해 같이 적은 것이 있다.

**이 셋들은 엔진을 깨뜨리려고 쓴 문장이다.** 회차마다 엔진이 못 보는 자리를
겨냥해 만들었고, 모델을 겨냥해 만든 셋은 열세 회차 동안 하나도 없다. 개발셋이
규칙 쪽으로 기울었던 만큼 이 셋들은 반대로 기울어 있다 — **어느 쪽도 중립적인
벤치마크가 아니다.** 그럼에도 모델은 이 셋을 한 번 보고 저 숫자를 냈고, 엔진은
같은 자리에 도달하는 데 회차 하나와 여덟 묶음의 수정이 필요했다.

## 그래서 규칙에 판정 권한을 남겨 두는 이유를 다시 적었다

정확도로 정당화하던 자리가 무너졌으므로, 남는 것을 네 줄로 적었다. 전부 이 표
안에서 확인되는 것들이다.

1. **공식 근거 0.0 은 실행 결과가 아니라 구조다.** 네 열 중 유일하게 뒤집히지
   않는 칸이다. 모델은 검증 가능한 출처 ID 를 만들 수 없고, 만들게 하면
   그것이 곧 지어낸 근거다.
2. **고친 것이 남는다.** 엔진의 0.4384 → 0.9783 은 커밋 여덟 개이고 회귀를
   CI 가 잡는다. 모델의 0.9677 은 다음 모델 버전에서 조용히 달라진다.
   우리가 고칠 수 있는 것은 한쪽뿐이다.
3. **모델이 죽으면 판정이 사라진다.** 164건 실패 0건은 이 실행의 결과이지
   보장이 아니다.
4. **판정이 맞아도 행동이 반대일 수 있다.**

## 4번이 오늘의 진짜 발견이다 — `fh-1178`

```
거래처 대금이 입금 처리되었습니다. 세금계산서는 다음 주에 발행됩니다.
  label : is_fraud=False, 천장 high (state=shared_account_access)
  모델  : is_fraud=False, risk=high      ← 여기까지 맞다
          actions=[..., STOP_CONTACT, ...]
```

정상 문장이고 모델도 정상으로 봤다. 상태 때문에 등급 천장이 `high` 인 것까지
맞혔다. 그러고서 **거래처와 연락을 끊으라고 했다.**

이것이 v1.2 회차가 이름 붙인 **"상태만으로 상대를 끊으라고 하지 않는다"** 다.
상태는 읽는 사람이 무엇을 했는지만 말하고, `STOP_CONTACT` 만 방향이 반대라
상대가 적이라는 판단이 먼저 있어야 한다. 엔진에서는 게이트 한 줄이고, 모델에서는
프롬프트에 적어 두고 지켜지기를 바라는 것 말고 할 수 있는 일이 없다.

**이 자리가 이 제품이 하이브리드인 이유를 정확도보다 잘 설명한다.** 판정이 맞은
사용자에게 틀린 행동이 나가면, 판정이 맞았다는 사실은 아무 일도 하지 않는다.

금지 행동은 164건 중 6건이었다. 그런데 여섯이 한 덩어리가 아니다.

| 사례 | 낸 금지 행동 | 성격 |
|---|---|---|
| `fh-1178` | `STOP_CONTACT` | **위험** |
| `fh-1109` `fh-1125` `fh-1147` `fh-1184` `fh-1034` | `VERIFY_OFFICIAL_CHANNEL` | 소음 |

다섯은 쓸데없는 조언이고 하나는 틀린 조언이다. `forbidden_action_avoidance` 는
0.9677 하나로 접히므로 **이 구분은 지표가 아니라 사례를 봐야 나온다.**

## 모델의 미탐 3건은 전부 같은 어형이다

```
fh-1015  관세청 통관관리과입니다. … 저희 쪽에서 순차적으로 연락드리겠습니다.
fh-1016  우체국 등기 담당입니다. … 별도 문의는 받지 않으니 연락을 기다려 주십시오.
fh-1117  병무청 병역관리과입니다. … 담당자가 확인 후 연락드릴 예정입니다.
```

셋 다 `is_fraud=False, risk=low` 다. 요구가 없고 링크가 없고 문체가 공손하니
그냥 통지문으로 읽힌다.

v1.2 회차의 **창구 독점**이다 — 사칭은 읽는 사람의 창구를 닫는다("별도 문의는
받지 않으니"). 표지가 요구에 **있는** 것이 아니라 **없는** 것에 있어서, 문장을
읽고 판단하는 쪽에는 잘 안 보인다. 엔진도 v1.2 회차 전에는 못 봤다.

**두 셋에 걸친 미탐 3건이 전부 이 한 어형이라는 것**이, 다음 셋을 무엇으로
채워야 하는지를 말한다 — 열세 회차 동안 만든 셋은 전부 엔진을 겨냥했고,
모델을 겨냥한 셋은 아직 없다.

## 모델의 오탐 1건도 이름이 있다

```
fh-1011  사이버범죄 신고 접수 확인 메일입니다. …   label: 정상
  모델 : is_fraud=True, risk=high, actions=[STOP_CONTACT, …, CONTACT_KISA_118]
```

**진짜 신고 접수 확인문이다.** 읽는 사람이 자기가 낸 신고의 접수번호를
안내받았는데 모델은 고위험 사기로 올린다. v1.2 의 "진짜 기관도 문자를 보낸다"
이고, 엔진이 그때 여덟 건 중 여덟을 틀렸던 자리다. 모델은 열둘 중 하나를
틀린다.

## 검증

```
pytest -q                    1094 passed, 2 skipped   (신규 2건)
stub 배관 통과 후 유료 3건 → 84건 → 80건
164건 실패 0 / 어휘 밖 코드 0
```

새 테스트 둘.

- `LlmJudgement.case_id` 가 열두 셋 + 개발셋의 **모든** 번호를 받는지, 그리고
  `CASE_ID_PATTERN` 공유가 풀리지 않았는지
- 판정 파일의 `dataset_id` 가 sha256 과 같은 셋을 가리키고, 사례를 하나도
  빠뜨리지 않았는지

## 보안·비용 영향

- 새 외부 표면 없음. 판정자는 `evaluation/` 에 있고 `app/` 어디에서도 부르지
  않는다 — 요청 경로에는 이 코드가 없다.
- 결과 파일에 원문도 모델 응답 본문도 없다. 실패는 **종류**만 남는다(adr/0006).
- 유료 호출 167건(프로브 3 + 84 + 80). 예산 알림 ₩10,000/월은 어제 걸어 뒀다.
- 결과를 커밋했으므로 CI 와 심사자는 **유료 호출 없이** 같은 표를 다시 만든다.

## 남은 것

1. **판정 프롬프트 v0.2.** 지금 결과는 프롬프트 한 벌짜리다. v0.2 가 나오면
   같은 두 셋을 다시 돌려 그 한계를 좁힌다.
2. **모델을 겨냥한 셋.** 미탐 3건이 전부 창구 독점이었다.
3. **설명 문장 품질.** 여전히 분모가 0 이다. 오늘 잰 것은 전부 탐지와 행동이다.
4. 나머지 열 셋은 판정시키지 않았다 — 이미 엔진 수정에 쓰였고 동결 시점 열이
   없는 것도 있어 같은 조건의 비교가 되지 않는다.
