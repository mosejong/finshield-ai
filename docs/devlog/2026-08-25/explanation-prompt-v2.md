# 2026-08-25 — 겨냥한 곳은 못 맞히고 다른 다섯 곳을 맞혔다 (지시문 v2)

## 왜 지금

앞 회차가 분모를 채우고 나서 남긴 숫자는 하나였다.

> 164건 중 6건에서 모델이 근거에 없는 전화번호를 만들었다. 여섯 중 다섯이 이미
> 돈이나 계좌 권한이 움직인 뒤였다.

검증기가 전부 막았으니 사용자에게 나간 잘못된 번호는 없다. 그런데 막았다는 것은
**그 다섯 명에게 "왜 위험한지" 가 비어서 갔다**는 뜻이기도 하다. 지금 전화를 걸
참인 사람에게 설명이 사라지는 자리다.

앞 회차 devlog 의 "남은 것" 첫 줄이 `프롬프트 v0.2 — 근거가 비면 연락처를 내지
말 것. 고치면 재측정` 이었다. 그 줄을 지우러 갔다.

## 무엇을 바꿨나

`fraud_explanation_v1` → `fraud_explanation_v2`. 세 줄이 늘었다.

1. `[사용자가 받은 문자]` 는 근거가 아니다. **거기 적힌 번호와 기관명은 보낸 쪽이
   고른 값이다.**
2. 세 칸에 전화번호가 없으면 설명에도 쓰지 않는다. 어디로 연락하라고 말하는 대신
   **무엇이 정상 절차와 다른지**만 말한다.
3. medium/high 에서는 그 문자가 안전하다고 말하지 않는다.

1 과 2 는 같은 이야기의 두 각도다. 하나는 출처를 부정하고, 하나는 그 자리에 무엇을
넣을지 지정한다. **금지만 적으면 모델은 금지된 것을 뺀 자리에 다른 것을 넣는다.**

v1 은 지우지 않고 `FRAUD_EXPLANATION_PROMPT_V1` 로 남겼다. 나아졌다는 말은 무엇과
비교했는지가 남아 있을 때만 확인 가능한 주장이다. 사본이 정확한지는 테스트가 본다 —
계산한 sha256 이 **v1 시절에 먼저 박혀 있던** 값과 맞는지 비교하므로, 계산해서 항상
통과하는 검사가 아니다.

**한 회차에 한 변경.** 엔진도 셋도 모델도 그대로다.

## 잰 것

held-out v1.2(80건)·v1.3(84건)을 v2 로 다시 태웠고, **같은 조건으로 한 번 더**
태웠다. 총 네 실행, 328시도.

| | v1.2 v1 | v1.2 v2 | v1.2 반복 | v1.3 v1 | v1.3 v2 | v1.3 반복 |
|---|---:|---:|---:|---:|---:|---:|
| 설명 나감 | 79/80 | 79/80 | 79/80 | 84/84 | 84/84 | 84/84 |
| 대체 모델 사용 | 4 | 1 | 1 | 3 | 3 | 0 |
| 근거 이탈 | 5 | 2 | 2 | 3 | 3 | 0 |
| **지어낸 연락처** | **5** | **2** | **2** | **2** | **0** | **0** |
| 판정 뒤집기 | 0/57 | 0/54 | 0/54 | 1/52 | 3/52 | 0/49 |
| 안전 필터 차단 | 0 | 0 | 0 | 0 | 0 | 0 |
| 길이 p50 | 233 | 217 | 220 | 220 | 201 | 203 |

**지어낸 연락처가 7시도 / 6사례 → 2시도 / 1사례.** 두 실행에서 같은 값이고 두 셋에서
방향이 같다.

사라진 다섯 건:

```
v1.2  fh-1038 [high]  fh-1040 [high]  fh-1065 [high]
v1.3  fh-1147 [high]  fh-1170 [high]
```

전부 `high` — 앞 회차가 "이미 돈이 움직인 뒤" 라고 적은 그 사례들이다. 그리고 다섯
모두 v1 에서 **주 모델이 거부당하고 대체 모델이 받아 준** 자리였다. 결과 문장은
안전했지만 그 안전을 검증기와 재시도 한 번으로 사고 있었다. 대체 모델 사용이 4→1,
3→0 으로 준 것이 같은 사실의 다른 면이다.

## 겨냥한 한 건은 못 고쳤다

두 번째 규칙은 **`fh-1007` 을 보고 쓴 문장이다.** 그리고 `fh-1007` 은 그대로다.
주 모델도 대체 모델도 여전히 거부당한다.

같은 사례를 다시 불러 봤다.

```
gemini-3.6-flash       → rejected_invented_contact   걸린 토큰: 112
  "…경찰청 112 신고 관련 처리가 진행 중임을 알리는 일반적인 안내 문자입니다."

gemini-3.1-flash-lite  → rejected_invented_contact   걸린 토큰: 112
  "해당 문자는 112 신고 접수 결과에 대한 안내로 확인됩니다."
```

**모델은 어디로 연락하라고 말하고 있지 않다. 이 문자가 무엇인지 말하고 있다.**
지시문은 "연락처를 쓰지 말라" 고 했고 모델은 연락처를 쓰지 않았다 — `112` 는 설명
대상의 이름으로 들어가 있다.

검증기의 연락처 패턴은 문장 어디에 있든 번호를 잡는다. **"112 로 전화하세요" 와
"이것은 112 안내입니다" 를 구분할 수 없다.** 구분하려면 문장의 의도를 읽어야 하고,
그건 정규식이 하는 일이 아니다.

이 회차에서 가장 중요한 건 이 한 줄이다 — **규칙은 자기가 겨냥하지 않은 다섯 곳을
고쳤고, 겨냥한 한 곳은 못 고쳤다.** 프롬프트로 고칠 수 있는 문제와 없는 문제가
여기서 갈렸다.

## 검증기를 열지 않는다

손대고 싶은 자리는 검증기다. "안내입니다" 같은 서술형 문맥을 예외로 두면 마지막
1건이 사라지고 표가 깨끗해진다.

하지 않는다. **두 방향의 오류가 같은 값이 아니다.**

| | 잃는 것 |
|---|---|
| 잘못 거부 | 설명 문장 하나. 위험 수준·신호·행동·근거는 그대로 나간다 |
| 잘못 통과 | 사기범이 고른 번호가 "공식 안내" 의 얼굴로 사용자에게 간다 |

한쪽이 압도적으로 비싸면 모호한 자리는 **비싼 쪽을 피하는 방향으로** 닫는다.
표의 숫자를 예쁘게 만들려고 검증기를 여는 것은 정확히 반대 방향이다.

고칠 자리는 프롬프트도 검증기도 아니다. `build_grounded_text` 가 `- 없음` 세 줄이면
모델이 무엇을 쓰든 정의상 근거 밖이고, **지시문으로 그 사실을 바꿀 수는 없다.**
**근거가 비면 모델을 아예 부르지 않는 것**이 답이고, 그건 다음 회차다. 실패가
아니므로 거부도 차단도 아닌 결과 이름이 하나 더 필요하고, `explained_rate` 의 분모를
어떻게 할지도 정해야 한다. 이번에 같이 넣지 않은 이유는 하나 — **두 변경을 한 번에
넣으면 줄어든 숫자가 어느 쪽 덕인지 말할 수 없다.**

## 1 과 3 의 차이에 이야기를 붙이기 전에

v1.3 에서 `rejected_contradicts_verdict` 가 1 → 3 으로 **늘었다.** 판정 뒤집기를
막으려고 규칙을 더한 회차에서 그 지표가 나빠졌다. 그대로 두면 표에서 "v2 가
악화시켰다" 가 저절로 읽힌다.

확인했다.

- 걸린 세 사례(`fh-1124`·`fh-1129`·`fh-1164`)를 각각 5번, 총 15번 재호출 → **0건 재현**
- 같은 셋을 통째로 한 번 더 → **0 / 49**

`temperature=0.0` 은 결정론을 보장하지 않는다. 그리고 이 표의 값은 한 자릿수다.
**같은 조건이 저절로 얼마나 움직이는지를 모르면 개선과 잡음을 가를 수 없다.**
그래서 반복 실행 파일을 저장소에 같이 넣는다 — 다음에 이 표를 읽는 사람에게 한 칸의
변화를 판단할 재료가 있어야 한다.

같은 잣대를 개선 쪽에도 댄다. 5→2, 2→0 은 두 실행에서 같은 값이고 두 셋에서 방향이
같다. 이쪽은 잡음으로 설명되지 않는다.

## 낡은 숫자가 `measured` 로 나가지 못하게 했다

`_explanation_layer` 가 셋의 sha256 에 더해 **지시문의 sha256** 도 본다. 다르면
`stale` 이다.

이 검사가 없었다면 이번 회차에서 정확히 이런 일이 일어났다 — 프롬프트를 바꾼 뒤에도
보고서가 v1 의 값을 계속 `measured` 로 내놓고, 읽는 쪽은 그것이 낡았다는 사실 자체를
모른다. **벤치마크가 스스로 낡았다고 말하지 못하면, 낡음은 발견되지 않는다.**

결과 파일 이름에도 지시문 판을 넣었다(`…-prompt-v1.json` / `…-prompt-v2.json`).
덮어썼다면 `docs/34` 13절이 인용하는 값이 조용히 사라지고 문서가 없는 숫자를
가리켰을 것이다. 이름·파일 안의 `prompt_id`·박아 둔 sha256 이 서로 맞는지는 테스트가
본다 — 이름은 손으로 붙이고, sha256 은 사람이 못 읽는다. 둘 다 있어야 한다.

## 곁가지

- **문장이 짧아졌다.** p50 233→217, 220→201. 제약을 더하면 모델이 말을 줄인다.
  600자 상한에서 한참 아래이므로 잘린 것이 아니다. 다만 짧아진 것이 **더 읽기 쉬워진
  것인지는 이 표가 답하지 않는다.**
- **안전 필터 차단은 네 실행 모두 0.** `docs/34` 9절이 가장 오래 걱정한 항목이
  328시도째에도 한 번도 일어나지 않았다.
- **대체 모델 호출이 줄어 비용도 줄었다.** 설계 목적은 아니지만 사실이다.

## 개인정보·보안 확인

- 결과 파일에 **모델이 만든 문장이 없다.** 건수·사유·소요시간·글자 수뿐이다
  (`adr/0006`). 테스트가 여섯 파일 전부에 대해 어휘 밖 문자열이 없는지 확인한다
- 진단용으로 모델 출력을 실제로 읽은 것은 임시 스크립트이고, 저장소에 넣지 않았다
- 새 외부 표면 없음. 프롬프트 문자열만 바뀌었고 호출 경로·타임아웃·모델은 그대로다
- 합성 골든셋이라 원문에 개인정보가 없다. 그래도 최소화 계층은 그대로 탄다

## 남은 것

- **근거가 비면 부르지 않기** — 이 회차가 이름을 붙인 자리. 다음 회차
- **검증기가 놓치고 통과시키는 문장** — `fh-1007` 이 알려 준 것은 검증기가 *의도* 를
  못 본다는 사실이고, 지금 그 눈먼 자리는 거부 쪽으로만 기울어 있다. 반대쪽은 아직
  아무 숫자도 없다
- **문장이 읽을 만한가** — 여전히 계약 준수율만 쟀다
- **모델이 놓치는 것을 겨냥한 held-out 셋** — 열세 셋 전부 엔진을 겨냥했다
