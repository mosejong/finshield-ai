## 변경 이유

이 프로젝트의 논지는 "hybrid 가 규칙만이나 모델만보다 낫다" 였는데, 그 문장을
뒷받침하는 숫자가 절반만 있었다. 규칙 쪽은 2026-08-13 에 쟀고(`docs/32`), 모델 쪽은
계약을 고정할 프로바이더가 없어 `not_run` 이었다. 2026-08-18~19 에 AI Studio
프로바이더가 들어오고 라우트까지 붙으면서 선행조건이 사라졌다.

**측정 없이 비교표를 쓰는 것이 이 시점에서 가장 쉬운 유혹이었다.** 대회 제출물에서
가장 설득력 있는 표가 이것이고, 규칙 쪽 숫자는 이미 좋다. 그래서 반대로 갔다 —
모델에게 우리 엔진의 일을 **통째로** 시키고, 모델이 이기면 이겼다고 적는다.

```

  골든셋 61건 ─▶ 엔진 실행 ─┐            │
```

핵심은 **유료 측정과 CI 집계를 분리한 것**이다. `evaluate_fraud_engine.py` 는 CI 가
매 푸시마다 돌리는 명령이라 네트워크도 비용도 없어야 한다. 판정은 한 번 하고 결과
61건을 그대로 커밋한다. 그러면 CI 도 심사자도 유료 호출 없이 같은 표를 다시 만들 수
있고, "어떤 데이터·모델·프롬프트로 잰 숫자인가" 가 파일 하나로 확인된다.

## 아키텍처 결정

**1. 판정자를 `evaluation/` 에 두고 `app/` 에 두지 않았다.** 제품은 모델에게 판정을
시키지 않는다(`CLAUDE.md` 첫 non-negotiable). 이 경로는 비교를 위해 일부러 만든
것이고, 요청 경로 코드가 이것을 import 하는 날은 경계가 깨진 날이다. 위치 자체가
그 사실을 말하게 했다.

**2. 프롬프트 sha256 을 계산하지 않고 리터럴로 적었다.** `app/services/llm/
explanation.py` 와 같은 방식이다. 계산하면 항상 일치해서 아무것도 증명하지 못한다.
프롬프트를 한 글자 고치면 검사가 깨지고, 고친 사람이 재측정하게 되는 것이 의도다.

**3. 골든셋 sha256 을 판정 결과에 함께 적는다.** 데이터가 바뀌었는데 재측정하지
않으면 `llm_only.status` 가 `stale` 이 되고 `--check` 가 `llm_only_stale` 로
실패한다. 비교를 포기할 때의 탈출구는 결과 파일 삭제이며, 그러면 `not_run` 으로
돌아간다. **낡은 숫자를 조용히 계속 싣는 경로만 없앴다.**

**4. 집계에서 모델에게 유리해질 수 있는 길 세 개를 전부 막았다.**

- 답하지 못한 호출은 제외가 아니라 **"경고 없음"** 으로 센다. 빼면 모델이 답한 것만
  고른 점수가 된다.
- 판정에 없는 `case_id` 는 `missing_judgement` 실패로 채운다. 분모가 줄지 않는다.
- 낡은 실행은 위 3번으로 거부한다.

**5. 모델에게 엔진과 같은 입력과 같은 출력 어휘를 줬다.** 사기 유형 6개, 위험 수준
3단계, 행동 코드 11개를 코드와 제목까지 프롬프트에 적었다. 숨기면 모델 능력이 아니라
프롬프트 설계를 재게 된다. 다만 `STATE_MINIMUM_RISK` 정책표는 주지 않았고, 그래서
상태 정책 정확도 0.508 은 "주지 않은 정책의 준수율" 이다 — `docs/32` 에 그대로 적어
뒀다.

**6. Hybrid 의 탐지 숫자는 엔진과 동일하다.** 우연이 아니라 구조다.
`explain_analysis` 가 `AnalyzeResponse` 를 받아 `str | None` 을 돌려주므로 모델
출력이 위험 수준·유형·행동에 닿을 경로가 타입에 없다. 그 동일함을 검사 하나가
고정한다. 두 숫자가 갈라지는 날은 경계가 깨진 날이다.

**7. 품질 게이트는 엔진 숫자만 본다.** 모델 쪽에 기준선을 걸면 Google 이 모델을
바꾼 날 우리가 고칠 수 없는 이유로 CI 가 빨개진다. 게이트가 막는 것은 "낡은 비교"
하나뿐이다.

같은 예측 벡터로 계산했으므로 추가 비용은 없다. 결과 JSON 의
`hybrid_v0_1.alternatives_considered` 에 남겼다.

|---|---:|---:|---:|---:|
| 규칙 ∪ 모델 | 0.928571 | 1.000000 | 0.962963 | 0.136364 |

교집합은 표에서 가장 예쁘다 — 오탐 0, 정밀도 1.0. **그런데도 넣지 않았다.** 두 조합
모두 모델이 최종 경고 여부를 움직이므로 첫 non-negotiable 을 어기고, 교집합은 특히
**모델이 죽으면 경고가 사라지는** 구조다. 지금 위험한 문자를 받은 사람에게 외부 API
장애가 곧 무경고가 되는 설계는 숫자로 고를 자리가 아니다. 숫자와 함께 이유를 남겨
둔 이유는, 나중에 이 표를 다시 보는 사람이 "왜 안 썼지" 를 재발견하지 않게 하려는
것이다.

## 공식 근거와 provenance

이 작업은 공식 데이터를 새로 끌어오지 않는다. 행동 코드에 붙는 출처는 기존
scenario engine 의 `action_source` 를 그대로 쓴다. 모델 경로의 근거 coverage 를
0.0 으로 기록한 것은 **없는 것을 없다고 적은 것**이며, 채우려면 지어내야 한다.

## 보안·개인정보 영향

- 골든셋은 전부 팀이 직접 쓴 합성 문장이다. 실제 피해 메시지나 개인정보가 외부
  프로바이더로 나가지 않는다.
- 그럼에도 제품과 **같은** 최소화 계층을 통과시켰다. 평가 경로만 예외를 두면 그
  예외가 나중에 제품으로 새는 길이 된다.
- 스크립트는 원문도 응답 본문도 출력하지 않는다. 진행 상황은 건수와 실패 **종류**
  로만 찍는다(`adr/0006-privacy-safe-observability.md`).
- API 키는 `GEMINI_API_KEY_FILE` 경로로만 읽고 어디에도 찍지 않는다.
- 유료 호출이 기본값으로 나가지 않는다. `FINSHIELD_LLM_PROVIDER=google_ai_studio`
  가 아니면 스크립트가 즉시 종료한다. `llm/runtime.py` 의 스위치를 그대로 존중하며,
  자기만의 켜는 길을 만들지 않았다.

## 실패, 수정, 리뷰 이력

- `python -c` 가 `ModuleNotFoundError: pydantic` 으로 죽었다. 시스템 파이썬에는
  의존성이 없다 — 이후 전부 `.venv/Scripts/python.exe` 로 돌렸다.
- 스크립트가 `fraud_benchmark._normalized_dataset_sha256` 을 `# noqa` 로 끌어 쓰고
  있었다. 모듈 간 비공개 import 는 경계를 지운다. 함수를 공개
  `normalized_dataset_sha256` 으로 올리고 호출부 둘을 고쳤다.
- `FRAUD_JUDGE_PROMPT_SHA256` 을 처음에 자리표시자로 넣었다. 실제 값을 계산해 리터럴
  로 교체했다 — 저장소의 기존 관례(계산 금지, 리터럴)를 그대로 따랐다.

## 알려진 위험과 다음 작업

- **프롬프트 한 벌, 모델 한 개, 실행 한 번이다.** 다른 프롬프트로 재면 달라진다.
  이 표는 "이 조건에서 이랬다" 이지 모델 일반 능력의 측정이 아니다.
- **골든셋 61건은 엔진 교정에 쓰인 개발셋**(`held_out: false`)이다. 규칙 쪽에 유리한
  편향이며, 그럼에도 탐지에서 모델이 앞섰다는 사실이 위 결과를 오히려 강화한다.
  held-out v0.2 는 `docs/28` P2-1 에 남아 있다.
- **v0.2 에서 규칙 어휘를 넓힌다.** 모델이 찾아 준 `fg-046`·`fg-047` 은 규칙 신호
  어휘의 구멍이다. 모델을 판정에 넣는 것이 아니라 **모델이 찾아 준 구멍을 규칙으로
  메우는** 방향이다.
- **설명 문장 품질은 여전히 안 쟀다.** 근거 이탈률, 안전 필터(SAFETY finishReason)
  차단율, prompt injection 골든셋 — 위 숫자는 전부 탐지·행동에 대한 것이다.
- **비용 상한이 없다.** 유료 등급에 자동 정지가 없어 선불 크레딧 ₩70,000 이 유일한
  천장이다. 예산 알림 설정은 `docs/31` 11-5, `docs/34` 9절과 같은 항목이다.
