## 비범위

- 배포(제출물 ③)는 이번에 하지 않는다. VM 접속에 브라우저 Cloud Shell 이 필요해

## 이 문서들을 쓰는 원칙

**하나뿐이다 — 저장소에 없는 기능은 명세에 적지 않는다.**

기획서는 설득하는 문서이므로 없는 것을 있는 것처럼 쓰고 싶어진다. 그렇게 쓰면
심사에서 URL 을 열어 보는 순간 무너진다. 그래서 기능명세서 13절을 **"미구현·제한
사항"** 으로 따로 두고, 정적 fixture 로 남은 세 곳을 이름과 파일 경로까지 밝혔다.

| 아직 fixture | 파일 |
|---|---|
| 신호별 "왜 위험한가" 문구 | `web/lib/mock/analysis.ts` |
| `/check/result/demo` 데모 결과 | `web/lib/mock/analysis.ts` |
| 프로필 입력 전 예시 화면 | `web/lib/api/home.ts` |

그 대가로 **"위험 판정·행동·근거·금융 계산은 전부 live 백엔드 값"** 이라는 문장을
쓸 수 있게 됐다. 경계를 그어야 그 안쪽을 주장할 수 있다.

## 발견하고 고친 것

### 1. 위험 신호는 11종이 아니라 12종이다

기획서 초안에 "위험 신호 11종"이라고 썼다. `SIGNAL_RULES` 가 11개인 것은 맞지만
URL 형태 분석이 만드는 `suspicious_link` 가 12번째 신호 코드다. 제출 문서에 실제
응답과 다른 숫자가 들어갈 뻔했다. **"문구 규칙 11종 + URL 형태 1종"** 으로 고쳤다.

### 2. 만점인 것은 이진 판정뿐이다

두 문서 모두 F1 1.000000 을 적으면서 "개발셋이 변별력을 잃었다"는 해석은 달아
두었는데, **사기 유형별 분류가 만점이 아니라는 사실은 빠져 있었다.**

```
loan_policy_impersonation  F1 0.909091  (recall 0.833333)
money_mule_transfer        F1 0.923077  (precision 0.857143)
```

"위험하다"는 판단은 개발셋에서 다 맞혔지만 **유형 이름을 붙이는 데서는 여전히
틀린다.** 두 문서와 README 세 곳에 모두 넣었다. 만점 옆에 만점이 아닌 숫자를
같이 두지 않으면, 해석 문단이 아무리 정직해도 표만 읽는 사람에게는 거짓이 된다.

### 3. README 의 Status 가 4일 낡아 있었다

`README.md` 가 v0.1 수치(precision 0.973684, recall 0.948718, F1 0.961039,
FPR 0.045455)를 그대로 들고 있었고, **"LLM-only와 Hybrid 비교도 아직 수행하지
않았다"** 고 적혀 있었다. PR #68 에서 이미 유료 측정을 마쳤으므로 사실이 아니다.

같은 줄에서 세 가지를 고쳤다.

- 판정 경로에 LLM 이 없다는 문장을 **"판정 경로에는"** 으로 한정했다. 설명
  엔드포인트가 생긴 뒤로는 "LLM 없이 동작한다"가 통째로는 참이 아니다.
- Next priorities 에서 완료된 항목(LLM-only 비교)을 빼고, held-out v0.2 를
  **"이제 추가 측정의 전제 조건"** 으로 승격했다.
- 제출물 두 편의 위치를 Status 최상단에 적었다.

## 아키텍처 결정

### 기획서와 기능명세서에서 같은 숫자가 나와야 한다

두 문서가 같은 측정치를 각자 적으면 반드시 갈라진다. `docs/README.md` 에 출처를
`evaluation/results/fraud-benchmark-v0.1.json` 하나로 못 박고, 재측정 시 35·36·32·33
을 **함께** 고쳐야 한다고 적었다. 문서가 넷이면 넷 다 고치는 것이 규칙이 되어야
한다.

### 부록 A 는 제출하지 않는다

기획서 부록 A(제출 전 확인 목록)에 **"제출 문서에 포함하지 않음"** 을 명시했다.
저장소 안에서는 체크리스트가 유용하지만 심사자에게 우리 내부 TODO 를 보낼 이유가
없다.

### 한계 절을 뒤가 아니라 앞에서 읽어도 되게 썼다

기획서 10절에 **"심사에서 이 절을 먼저 읽어도 무방하다"** 를 넣었다. 한계를 감추면
심사자가 직접 찾아냈을 때 문서 전체의 신뢰가 무너진다. 먼저 밝히면 나머지 주장이
검증된 것으로 읽힌다.
