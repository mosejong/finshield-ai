# 2026-08-19 — 전세보증금 위험 점검 v0.1 (백엔드)

## 왜 지금

공모전 제출물을 채우려고 만든 것이 아니다. 질문이 바뀌었다 — "심사에서 뭐가
좋아 보이나" 가 아니라 **"사회초년생이 실제로 부족한 게 뭔가"** 다.

세 가지를 놓고 골랐다.

| 후보 | 판단 |
|---|---|
| **전세보증금 위험 점검** | 채택 |
| 청년 정책금융 매칭 | 탈락 — 공식 데이터 소스가 없다. 상품 조건을 코드에 박으면 CLAUDE.md 의 "상품·금리·적격성을 지어내지 않는다" 를 정면으로 어긴다 |
| 실수령액 계산기 | 탈락 — 이미 널려 있고 차별점이 없다 |

전세를 고른 이유 셋.

1. **손실 규모.** 보이스피싱 한 건과 보증금 한 건은 자릿수가 다르다. 그리고
   보증금은 대개 그 사람이 가진 전부다. 이 저장소에는 그 영역 코드가 한 줄도
   없었다.
2. **구조가 맞는다.** 사기 엔진은 이미 "어디까지 갔는가" 로 최소 위험을 올린다.
   전세 계약도 같은 모양이다 — 뒤로 갈수록 되돌릴 수 없다.
3. **LLM 이 낄 자리가 없다.** 부채비율은 나눗셈, 대항력 발생일은 법문에 적힌
   날짜 덧셈이다. 둘 다 결정론으로 끝난다.

## 코드보다 근거를 먼저 확인했다

한 줄도 쓰기 전에 링크부터 열었다. 6건을 실제로 열어 내용을 읽었고, **못 연 것은
넣지 않았다.**

| 확인됨 | |
|---|---|
| 주택임대차보호법 제3조(대항력 등) | 제1항 원문까지 확인 |
| 법제처 대항력·우선변제권 취득 | 요건과 근거 조문(제3조의2 제2항) 명시 확인 |
| 법제처 임차권등기명령 신청 | 신청 요건·효과 확인 |
| 법제처 부동산등기부 확인 | 확인 |
| 주택도시보증공사 전세보증금반환보증 | 확인 |
| 전세사기피해자 지원 특별법 제3조 | 시행 2026-05-12, 법률 제21634호 |

**실패한 것:** 주택임대차보호법 **제3조의2(보증금의 회수)** 조문 직링크. 국가법령
정보센터가 본문을 프레임으로 그려서 자동 확인이 되지 않았다. `lsJoLnkSeq` 를
+1 해서 맞춰 볼까 하다가 그만뒀다 — 맞춰 본 링크는 확인한 링크가 아니다.

그래서 우선변제권 근거는 조문 직링크 대신 법제처 안내 페이지를 인용한다. 대가가
있다. 그 페이지에는 "법적 효력을 갖는 유권해석의 근거가 되지 않는다" 는 자체
고지가 있다. 그래서 이 서비스는 그 페이지를 **어디서 확인하라는 안내**로만 쓰고
판단 근거로 인용하지 않으며, 그 사실을 `docs/37` 6절에 적어 두었다.

## 아키텍처 결정

### 60%·80% 는 우리가 정한 숫자다

어떤 기관도 이 구간을 고시하지 않았다. 문서에만 적으면 화면 캡처가 돌아다닐 때
사라지므로 **세 곳**에 박았다 — 응답의 `band_is_service_rule`, 신호 문장,
`disclaimer`. 테스트가 셋 다 고정한다.

### 모르는 값을 0 으로 채우지 않는다

선순위 채권최고액을 0 으로 두고 계산하면 비율이 실제보다 **낮게** 나온다. 즉
등기부를 아직 안 본 사람에게 가장 안전해 보이는 숫자를 준다. 정확히 반대로 가야
한다. 그래서 `unknown` 을 돌려주고 등기부 확인을 행동으로 민다.

이게 이 기능에서 가장 쉽게 틀릴 수 있는 자리였다.

### 대항력은 날짜를, 우선변제권은 참/거짓만 돌려준다

제3조 제1항이 "그 다음 날부터" 라고 적고 있으므로 `전입신고일 + 1일` 은 해석이
아니라 옮겨 적기다.

우선변제권은 요건이 명확한 것과 **취득 시점을 날짜 하나로 단정하는 것**이 다르다.
후자를 하려면 법문에 없는 해석을 얹어야 한다. 그래서 요건 충족 여부만 돌려준다.
`docs/36` 13절의 규칙과 같은 줄이다 — 없는 것은 없다고 한다.

### 점수를 만들지 않았다

사기 분석에는 `risk_score` 가 있다. 여기에는 없다. 가중치를 조정할 실측
데이터(골든셋)가 아직 없기 때문이다. 없는 정밀도를 숫자로 흉내 내지 않는다.

### 할 수 없는 일은 시키지 않는다

- 계약 전에는 가입할 계약이 없고, 미반환 뒤에는 손실을 보증으로 되돌릴 수 없다.
  두 끝에서 "보증 미가입" 신호와 가입 행동을 뺐다.
- 이미 마친 확인은 행동 목록에서 제거한다. 끝난 일이 남아 있으면 목록 전체의
  신뢰도가 떨어지고 진짜 남은 일이 묻힌다.
- `moved_in` 단계 최소 위험은 low 다. 절차를 마친 사용자를 단계만으로 겁주지
  않는다.

### 나열 순서가 알파벳순이면 절차가 뒤집힌다

첫 실행에서 `GET_CONFIRMED_DATE` 가 `REPORT_MOVE_IN` 보다 앞에 나왔다.
대항요건이 먼저 서야 그 위에 확정일자가 얹힌다. `ACTION_ORDER` 로 고정했고
테스트가 순서를 지킨다.

### 출처 무결성 규칙은 한 벌만 둔다

`app/domain/official_sources.py` 로 뽑아 fraud 와 housing 이 같이 쓴다. 두 벌로
두면 한쪽에만 검사가 추가되고 다른 쪽은 조용히 느슨해진다. 그 상태는 "출처가
검증됐다" 는 말을 도메인별로 다른 뜻으로 만든다.

**데이터 파일은 나눴다.** `supports` 가 행동 코드라서 섞으면 사람이 눈으로
대조해야 하고, 법령 조문과 스미싱 안내는 바뀌는 속도가 다르다.

## 보안·개인정보 영향

- **새 외부 호출 없음.** 런타임 웹 조회, URL fetch, 외부 API 모두 없다.
- **새 저장 없음.** 요청값을 DB 에 쓰지 않는다. 보증금·주택가격은 보관할 이유가
  없는 값이다.
- **새 민감 필드 없음.** 주민등록번호·계좌번호·주소·임대인 이름을 받지 않는다.
- **세션 요구 없음.** 그래서 소유권 검증 경계가 늘어나지 않는다.
- 로그는 기존 미들웨어가 남기는 route·상태·latency 뿐이다. ADR 0006 경계 유지.
- LLM 미사용. 프롬프트 인젝션 표면이 늘지 않는다.

## 남은 것

1. **프론트엔드.** 엔드포인트에 닿을 화면이 없다. 다음 작업이다.
2. 평가셋. 없으므로 점수도 만들지 않았다.
3. 미납 국세·지방세 열람 — 근거 페이지 확인 후 확인 항목에 추가.
4. 공식 시세 조회 — 지금은 사용자가 직접 넣는다.
5. 제3조의2 조문 직링크 재시도.
