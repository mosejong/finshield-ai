# 자리에서 본다 — held-out v1.0 과 요구를 세는 자리의 우언적 금지

2026-08-24

## 한 줄

v0.9 가 다음 회차 몫으로 이름만 적어 둔 결함 다섯 개를 재기 위해 셋을 얼렸고, 다섯 개를
전부 고쳤다. 동결 시점 오탐 7 · 미탐 3 에서 **오탐 0 · 미탐 2** 로 갔고
(f1 0.8750 → 0.9730 · FPR 0.2188 → 0.0000), 등급 천장 정확도는 0.7813 → **1.0000** 이다.
덤으로 v0.9 가 여섯 회차째 안고 있던 오탐 둘이 닫혀 그 셋도 만점이 됐다.

## 0. 이번 회차의 방향

| 회차 | 수정의 방향 | 값을 치르는 자리 |
|---|---|---|
| v0.2~v0.5 | 넓히기 | 정상 문장 (오탐) |
| v0.6 | 좁히기 | 사기 문장 (미탐) |
| v0.7 | 올리기 | 정상 문장의 등급 (천장) |
| v0.8 | 넓히기 5 + 좁히기 1 | 양쪽 다 |
| v0.9 | 갈아 끼우기 + 올리기 1 + 좁히기 1 | 옛 셋의 라벨 |
| **v1.0** | **넓히기 5** | **정상 문장 (오탐과 천장)** |

다섯이 전부 넓히기다. 값이 **한 방향으로만** 치러진다는 뜻이고, 그래서 이 셋은 사기보다
정상을 세게 짰다. 정상 32건이 전부 천장을 선언하고, 그중 스물여섯 건이 **넓히려는 바로
그 어형을 쓰는 정상 문장**이다.

### 어휘로 피하지 않고 자리에서 본다

이 회차 전체가 이 한 문장에서 나왔다.

동결 시점 오탐 일곱 건 중 **다섯 건이 하나의 어형**이었다 — `-(으)면 안 됩니다`.

```
"인증번호는 어떤 경우에도 알려 주시면 안 됩니다"   → 요구 표지 `주시면` 이 걸린다
"공동인증서 비밀번호는 입력하시면 안 됩니다"       → 요구 어간 `입력` 이 걸린다
"출처를 알 수 없는 앱은 설치하시면 안 됩니다"      → 요구 어간 `설치` 가 걸린다
```

**하지 말라는 문장이 요구를 세는 자리에서 요구로 세어졌다.** 예방 안내문은 위험한 행동을
말리기 위해 그 행동을 입에 올려야 하고, 그래서 위험한 낱말이 전부 들어 있다.

고치는 방법이 두 가지였다.

1. `주시면 안` 을 요구 표지에서 뺀다 → 다음 회차에 `입력하시면 안`·`설치하시면 안` 이
   그대로 남는다. 어형은 무한하고 어휘는 유한하다.
2. **금지 앞자락을 잘라 내고 남은 말로 판단한다** → 어형 하나가 아니라 자리를 닫는다.

2번을 골랐다. `_is_prohibited` 가 이미 같은 원칙으로 서 있다.

### 얼리기 전에 여덟 건을 고쳤다

72건 초안을 라벨 없이 먼저 엔진에 던졌고, **여덟 건이 겨냥한 결함을 재현하지 않아
고쳤다.** 두 종류다.

- **행동 표가 절대 내보내지 않는 이름을 요구한 라벨** — v0.8 `fh-660` 과 같은 실수다.
  `money_transfer_request` 는 `DO_NOT_FORWARD_MONEY` 를 내지 않는다. 그 코드는
  `receive_and_forward_money` 신호나 `received_unknown_money` 상태에서만 나온다
  (`fh-810`·`fh-817`·`fh-830`·`fh-835`).
- **내 문장이 서툴러서 빗나간 사례** — `fh-826`("보내 줄 수 있어?" 는 부탁형 의문문이라
  요구로 세지 않는다), `fh-828`(`빼서 … 넣어` 는 v0.7 이 권한 위임에 쓴 순서 게이트이지
  재전달 어휘가 아니다).

`fh-828` 은 네 번 다시 썼다. "수수료 제외하고 다시 송금해" 는 `advance_fee_demand` 로
켜져 `money_mule` 가드 자리를 잃었고, 최종본 "계좌로 들어온 돈을 아래 주소로 전달해
주시면 됩니다" 가 되어서야 겨냥한 자리를 잡았다.

> **결함을 재현하지 않는 사례는 수정의 값을 재지 못하고 만점만 하나 더 얹는다.**

## 4. 다섯 수정 (`7604f65`)

### 4-1. 금지 앞자락을 잘라 낸다

```python
PERIPHRASTIC_PROHIBITION_PATTERN = re.compile(r"면\s*안\s*[되돼됩됐된될]")

def _strip_prohibited_segment(clause: str) -> str:
    matches = list(PERIPHRASTIC_PROHIBITION_PATTERN.finditer(clause))
    if not matches:
        return clause
    return clause[matches[-1].end() :]
```

`_has_reader_demand` 가 절 대신 이 나머지를 본다.

**자르는 것은 절 전체가 아니라 금지까지다.** 사기 문자는 아는 창구를 금지해 놓고 그
뒤에서 요구한다 — "창구 방문은 하시면 안 되고, 담당자에게 통장 사본을 보내 주셔야
합니다"(`fh-802`). 절을 통째로 버리면 이 요구가 함께 사라지고, 그러면 오탐 다섯을
지우는 대신 미탐 하나를 새로 만든다.

같은 통찰이 반대편도 닫는다. **금지된 창구는 창구 안내가 아니다.** 채널 안내 배제가
있는 이유는 그 절이 읽는 사람을 메시지 밖으로 내보내기 때문인데, 창구를 막는 절은 정확히
반대 방향이다. `_is_channel_referral` 도 같은 나머지를 본다. 오탐 다섯과 미탐 하나가
**한 수정으로** 닫혔다.

### 4-2. 채널 어휘에 스토어와 홈택스

```python
r"|공식 스토어|앱스토어|플레이스토어|홈택스"
```

동사에는 `진행`·`설치`·`내려받`·`다운로드` 를 더했다. 창구 이름이 **먼저** 걸린 자리에서만
보므로 "첨부된 앱에서만 설치해 주세요"(`fh-809`·`fh-812`)는 걸리지 않는다 — 그 앱은
목록에 없는 창구이고, **목록에 없다는 것이 곧 아는 창구가 아니라는 뜻**이다.

브랜드 이름을 여는 것이 아니라 이미 아는 창구의 이름만 넣는다. 재지 않은
이름(구글플레이·원스토어·정부24)은 넣지 않았다.

### 4-3. 긴급 어휘를 여섯에서 열둘로

`1시간 안에`·`30분 내`·`오늘 자정까지`·`내일까지`·`금일 중`·`마감 임박`.

**`LEGACY_RULES`(점수를 만드는 표)는 일부러 건드리지 않았다.** 같은 시간 표현을 평범한
청구서도 쓰기 때문이다("자동이체일이 내일이라 오늘 자정까지 잔액을 확인해 주세요",
`fh-854`). 이 어휘는 등급 조합과 설명에만 쓰이고, 정상 안내문의 점수는 0 그대로다.

### 4-4. 띄어 쓴 `대환 대출` 은 요구 게이트에

```python
request_gated_keywords=("대환 대출",)
```

무조건 층에 넣지 않았다. **띄어 쓴 형태는 정상 안내문이 쓰는 형태이기도 하다** —
"대환 대출 상담은 영업점 창구에서 신청하실 수 있습니다"(`fh-860`). 붙여 쓴 `대환대출` 은
광고 문구에 가깝고 띄어 쓴 쪽은 그냥 제도 이름이라, 같은 낱말이라도 자리가 다르다.
`지검` 을 두 층으로 나눈 것과 같은 이유다.

### 4-5. 고립 요구는 기관이 문자로 시키지 않는 요구다

```python
SENSITIVE_REQUEST_SIGNALS = frozenset({..., "secrecy_isolation"})
```

등급 조합은 이미 `{authority_impersonation, secrecy_isolation}` 이라고 적혀 있는데 이
목록에만 빠져 있었다. 그래서 **고립 요구 하나만 들고 오는 자칭이 켜지지 않았다** —
"서울중앙지검 수사팀입니다. 수사 기밀이라 가족을 포함해 누구에게도 말씀하지
마십시오"(`fh-822`)에서 `지검` 이 요구 게이트에 걸려 자칭이 사라진다. **넘겨줄 물건이
없을 뿐 요구가 없는 것이 아니다.**

고립 어휘에 `직원에게도 알리`(`fh-824`)와 `다른 곳에 연락하지`(`fh-823`)를 더했다.
기밀 유지는 여전히 넣지 않았다 — "외부에 공유하지 말아 주세요"(사내 공지, `fh-865`)는
화제를 집단 안에 두는 말이지 제3자 확인을 막는 말이 아니다.

### 4-6. 대출 짝의 나머지 한 칸

```python
frozenset({"loan_policy_offer", "credential_request"}),
```

`account_access_request` 와 `money_transfer_request` 는 앞선 회차가 채웠는데 인증정보
짝만 비어 있었다. **한도 조회에 비밀번호가 필요한 대출 창구는 없다**(`fh-821`).

## 7. 셋의 무결성을 수리했다 (`c77b782`)

동결 커밋이 데이터셋과 baseline 은 넣었는데 **얼린 셋을 지키는 테스트를 등록하지
않았다.** 등록하자마자 두 가지가 걸렸다.

### 7-1. v0.9 문장 두 개를 그대로 물려받고 있었다

```
fh-839 == v0.9 fh-741   "인증번호는 저희를 포함해 누구에게도 알려 주시면 안 됩니다."
fh-846 == v0.9 fh-767   "설치는 공식 스토어에서만 진행해 주세요."
```

하필 v0.9 가 기록해 둔 오탐 둘, 즉 **이번 회차가 갚으려던 바로 그 문장**이다. 그대로
두면 같은 수정을 같은 문장에서 두 번 재고, 소진된 셋의 점수를 새 셋의 점수로 되받는다.

**다시 쓰지 않고 뺐다.** 수정이 존재하는 지금 쓰는 문장은 수정을 알고 쓰는 문장이고,
이 둘은 애초에 새로 재는 것이 없었다 — v0.9 가 이미 재고 있었기 때문이다. 빼기는
결과를 좋게 만들 수 없는 유일한 편집이다. 실제로 시작점의 오탐이 9 에서 7 로 **줄었다.**

### 7-2. persona 가 셋 중 둘뿐이었다

여섯 건에 `unknown` 을 붙였다. 평가기는 persona 를 엔진에 보내지 않고 데이터셋 통계로만
쓰므로(`evaluation/fraud_benchmark.py:77`) **측정된 숫자는 한 칸도 움직이지 않는다.**
셋의 신원(해시)만 바뀐다.

### 7-3. baseline 은 동결 시점 엔진으로 다시 쟀다

수정 뒤에 baseline 파일을 다시 쓰는 것은 그 자체로 의심스러운 일이라 재현 절차를 커밋
메시지와 여기 둘 다 적는다.

```bash
git checkout c6e5ede -- app/domain/fraud/
PYTHONPATH=. python -m scripts.evaluate_fraud_engine \
  --dataset evaluation/data/fraud_holdout_v1.0.jsonl \
  --output evaluation/results/fraud-holdout-v1.0-before-fix.json \
  --performance-repeats 3
git checkout HEAD -- app/domain/fraud/
```

**동결 커밋의 엔진으로 잰 값이다.** 누구든 같은 명령으로 확인할 수 있다.

### 7-4. 그리고 그 자를 테스트로 박았다
